# 工作流停止接收修复与离线验证

日期：2026-10-11。仅修改MCU源码、离线测试及说明，编译但未烧录。没有连接串口、AixProbe、相机或机械臂，没有运动或激光输出，也没有重新打包PC EXE。

## 1. 已修复

- `Middle/jetson_vision.c` 原来使用单个工作流命令槽；同批完整串口帧中，后续START/HOME可覆盖尚未消费的ABORT。
- `handle_workflow_control()` 改为普通8槽FIFO及独立8槽ABORT队列，保留各请求SEQ。非法action明确拒绝；容量满返回BUSY，不覆盖已接纳的请求。相同待处理ABORT的SEQ合并，已消费的重复/冲突仍由原工作流缓存判断。
- 完整合法ABORT解码后，接收处理立即让出；服务线程不在该周期先消费其他业务。单次原始RX处理最多256字节，避免持续生产数据导致状态机一直得不到调度。
- ABORT到来及停止/故障锁建立时，原工作流、拍摄、定靶启动及扫描推进作废；停止期间拒绝新的运动推进。成功停止确认解除门后，已经收到的旧原始字节和跨边界半帧仍被拒绝，不会恢复旧扫描。解除时的字节快照和解锁处于同一临界区，防止中断插入旧数据。
- 心跳、只读SCAN QUERY、ABORT和关闭定靶仍可处理。心跳过期不妨碍显式停止，但新运动仍须合法心跳；物理安全故障优先。
- `APP/robot_workflow.c` 在停止确认等待或失败时保持接收门；仅成功确认解除。保持CAN停止应答、任务退出/队列清空和新鲜五轴稳定反馈要求，重复请求不续期，不自动HOME。

## 2. 保持的线上合同

```text
Jetson -> MCU: TYPE=06 / LEN=1 / payload=03 / SEQ=S
MCU -> Jetson: TYPE=81 / LEN=3 / payload=21 01 00 / SEQ=S  接受
MCU -> Jetson: TYPE=81 / LEN=3 / payload=20 06 00 / SEQ=S  成功确认
MCU -> Jetson: TYPE=81 / LEN=3 / payload=20 07 06 / SEQ=S  停止失败/超时
```

ACK和82扫描终止不能替代停止成功确认。拒绝旧START/HOME等用81的拒绝ACK，error=BUSY(05)；拒绝扫描推进仍用82。成功停止后用新SEQ显式开始新轮，不能重放旧缓存业务；保护门清理旧字节期间可能返回BUSY，不算接受。

本次没有新增线上TYPE/LEN/错误码，没有调整2秒停止确认预算，没有更改FK/DH、正式姿态、轨迹、100 mm初始相机深度门槛、5 mm安装量或激光参数。MCU仍只做原初始测距锁存；运动中有效深度、净距、数据过期及ABORT触发由Jetson负责。短时深度缺帧的宽限和连续停机阈值没有在本次擅自设置。
