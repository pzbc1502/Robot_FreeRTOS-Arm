## 1. 结论与范围

人的可控性、基础安全门控和定位精度均为目标，不能以提高速度为由放松已有条件。方案分两部分：

1. **三视图工作面精调：已明确的需求。** 扫描发现左脸、正脸或右脸目标后，由 Jetson 选择相应固定视图，机械臂复用现有配方到位；以该次实际到位姿态建立并锁定局部参考工作面，在面内进行视觉精调。避免侧脸目标仍只沿正视时的基座固定 X/Z 面修正。
2. **视觉精调内部粗精速度上限的连续过渡：建议实现方案，平滑性目标已确认。** 保留现有比例闭环和稳定对准计数，优先将误差门限处突然切换的两档限速改为有界、连续的限速函数。用户接受即使对准时间不缩短，只要粗精切换及运动命令更加平滑。具体插值区间、速度上限和是否增加命令变化率限制仍须在对应实现处确认；耗时仅作对比指标。

第一版复用现有扫描、三视图配方、FK/IK、CAN 和关节控制。扫描结束后自动 `HOME → 正视` 的链路可以保留，待最终真实到位后再显式选择本次工作视图。先回正视不意味着以后只能在正视精调。

本方案不逐痣估计皮肤真实切面，不做全脸三维重建、任意表面法线规划、新 AI/学习控制或额外控制架构。工作面是一次到位后固定的工程参考面，建议与该到位时的相机成像面平行，不能称为已测得的皮肤切面。自适应增益、图像质量补扫等不纳入本次最小改动，也不包装为已证明的创新。

“深度距离先不管”在本文中指：**不新增持续深度闭环、连续距离保护或新的距离策略；保留现有启动测距稳定锁存、距离资格及相关停止规则。** 不能据此删除已有测距门控。本文不宣称实机安全、临床安全或定位精度已得到验证，也不以先做新模型实验作为写文档或推进离线实现的前提。

## 3. 两层流程必须区分

| 层次 | 实际含义 | 本文对应部分 |

| 外层：观察位移动 → 视觉精调 | 机械臂移动到左/正/右固定视图，再以该次锁定工作面处理同一目标 | 第一部分；解决“在哪个方向、哪个参考面精调” |
| 内层：视觉精调中的粗/精限速 | 已经在同一工作面闭环，根据当前像素误差大小限制速度 | 第二部分；解决 30 px 附近两档限速的突变 |


## 4. 第一部分：坐标、方向与单位

### 4.1 每次到位建立一个固定工作面

使用三个坐标系：基座 B、程序末端/工具 T、相机 C。`R_B_T` 表示将 T 系方向变换到 B 系，`R_T_C` 表示将 C 系方向变换到 T 系。相机与末端刚性连接只说明 `R_T_C` 固定，**不说明它是单位矩阵**。

推荐在真实到位后获取同一批完整五轴反馈 `q*`，由 FK 求 `R_B_T(q*)`，再合成：

```text
R_B_C* = R_B_T(q*) · R_T_C
b1 = R_B_C* · [1,0,0]^T        # 到位时画面向右的基座方向
b2 = R_B_C* · [0,1,0]^T        # 到位时画面向下的基座方向
n  = b1 × b2                   # 工作面法向
p* = 本次到位的末端参考点
P  = { p* + a·b1 + b·b2 }       # a、b 为面内位移，单位 mm
```

将 `b1/b2/n`、本次视图、目标身份、选面代次及初始工具轴一起锁定。`b1/b2` 应为有限、正交的单位轴；若用旋转矩阵，应核对正交性和右手性。原点选择必须与程序使用的末端参考点一致，不把相机光心和工具作用点混称一个点。

可替代路线是为左/正/右提供可靠、已核对的面内轴或方向矩阵。两条路线选一条作为正式来源，不能在不同模块混用互相矛盾的参数。`robot_capture_view_angles_get()` 只给 J1/J4/J5 配方角，不足以代替实际完整五轴到位姿态。

**待确认：** `R_T_C` 或各视图方向矩阵、图像是否镜像/旋转、末端参考点定义及参数版本。缺失时不能保证像素修正方向正确；通过机械安装资料、现有标定记录和方向一致性检查确定，不以 `R_T_C=I` 补空。仅计算方向向量时不需要平移外参；若进一步计算光心、工具作用点或真实光线交点，则仍需相应位置关系，不能把本方案的方向变换扩称为完整手眼标定。

本次面在初始化后固定，不随每帧重新选法向。精调保持本次选择的接近方向，沿面内平移。相机随末端运动，不是固定在基座上。用户已确认“沿画面向右移动相机，静止目标在画面向左移动”；此关系用于核对闭环符号，不能据此推出相机轴与程序 X/Z 轴重合。

五轴现有实现核验位置与工具 Z 轴，不要求任意工具滚转。**待确认：** 所选局部范围内，实际工具轴及相机成像方向相对锁定参考的允许偏差。需在现有 FK/IK 回验基础上检查相机方向一致性；工具轴通过不等于完整相机朝向必然恒定。超出可接受偏差应限制范围或拒绝继续，不能悄悄重建工作面，也不能为此把首版扩成任意姿态规划。

### 4.2 像素误差先变为局部二维命令，再转基座 XYZ

误差始终来自**当前画面内同一目标相对瞄准参考**的位置。为便于说明，本文约定：

```text
ex = u_target - u_aim
ey = v_target - v_aim           # 单位 px，画面 u 向右、v 向下
[v1,v2]^T = A_view · [ex,ey]^T  # 有符号比例映射，输出 mm/s
v_B = b1·v1 + b2·v2            # 输出基座 vx、vy、vz，单位 mm/s
Δp_B = v_B · dt                # 送既有位姿积分与 IK，单位 mm
```

这是定义示意，不声称旧 Jetson 的 `dcx/dcy` 已采用相同正号。**待确认：** 当前双端误差正号、`u_aim/v_aim` 的实际来源、各视图 `A_view` 的符号/比例及是否有交叉项。应先核对实际发送实现与瞄准标定，再用已知方向响应确认闭环能减小误差；若旧定义相反，只在约定位置统一转换一次。

`A_view` 的速度增益单位是 mm/s/px；若采用位移型接口，比例才是 mm/px，不能混用。像素数不能直接当毫米。现有 −0.09/+0.09 是基座 X/Z 控制基线，不能未经变换照搬成三视图局部轴系数。只反转左右误差符号，也不能表达侧向工作面在基座下通常同时具有 X/Y/Z 分量的事实。

三维输出仍只有两个独立面内自由度：应满足 `n·v_B≈0`；本次不新增法向/深度速度。到位姿态不同时，Y 分量可能非零，不能丢弃；也不能从 `vy≠0` 推出新增了深度闭环。

**待确认：** 各视图在现有工作距离条件下的像素比例、实际相机/工具/输出光路关系及有效瞄准参考。内参不等于已完成像素到机械运动的整链路标定，画面中心也不能自动当作输出瞄准点。通过现有光路与标定记录确定适用条件；未明确前只能作软件/离线检查，不能宣称已能准确落到目标。这里不新增持续测距，也不删除原启动距离锁存。

建议由 Jetson 负责同一目标识别、像素误差和视图选择，MCU 负责工作面与基座变换、限速、IK 和运动门控。两端必须冻结唯一变换责任：若 MCU 按上述公式变换，Jetson 就发约定的像素误差；不能 Jetson 先转成基座量、MCU 又变换一次。

局部命令限幅后再变换到基座。还需满足既有基座分量和关节限制；若额外限幅，优先对整个向量乘同一缩放系数，避免单独裁剪某个基座分量而破坏 `n·v_B≈0`。现有设置函数会逐分量裁剪，拟实现应保证上游命令处于其限制内，或采用保持方向的共同缩放；不能仅接通 Y 就认为全部完成。

### 4.3 观察位与精调可达区域分开验收

现有配方：左视 J1/J4/J5 为 70°/330°/86°，正视为 90°/0°/83°，右视为 115°/35°/85°。它们是当前观察位配方，J2/J3 还受基础姿态影响，不能只凭这三个角推出完整局部工作面或可达空间。

**待确认：** 每视图允许的面内范围、方向偏差容差，以及目标可见性、关节/机构/线缆边界。先以当前五轴 FK/IK、关节范围和已有日志做离线局部检查，后续再在单独授权且关闭实际输出的条件下验收。越界、不可见或逆解不通过时停止并报告，不自动换目标、不默认退回正视继续。一次观察位到达不证明附近所有精调点可达，也不证明接近路径无碰撞。

## 5. 第一部分：最小完整实施顺序

以下步骤是同一首版的完整交付要求，基础门控不能留到后续再补。状态名称为逻辑含义，可在现有状态机内以少量子状态/标志实现，不要求照抄新增一套枚举。

| 顺序 | 动作与必须满足的条件 | 本步后允许的下一动作 |
|---|---|---|
| 1. 等待可选面 | 原测距锁存有效，扫描自动 HOME→正视链已真实完成；或处于另一个被明确允许的停止保持状态。没有故障、停止确认待完成或其他运动 | 接受一次显式 SELECT |
| 2. 接受本次选面 | 检查视图 1/2/3、心跳、急停/限位、姿态和忙状态；先关输出、撤销旧对准/输出资格，确认旧精调已停止、任务与队列交接完成 | 进入“工作视图移动中” |
| 3. 执行配方 | 复用 `robot_capture_request(SELECT,view)` 等已有执行链；整个切换期间禁止精调和输出 | 等待匹配本次请求的运动结果 |
| 4. 核验真实到位 | 结果成功后核对当前新五轴反馈、无活动运动/积压队列、所选配方及稳定条件；不能只看接受 ACK、完成缓存或固定延时 | 建立本次工作面 |
| 5. 初始化并绑定 | 以这次实际姿态锁定工作面，绑定当前目标/视图/选面代次；稳定计数、确认计数、旧许可、平滑器状态均复位 | 清旧视觉并等待新样本 |
| 6. 新样本预检 | 使解析器/工作流/目标模块中的旧误差资格、旧 ready 回调和旧样本缓存失效；等待属于本次绑定且在到位、初始化后新采集的当前同一目标样本 | 对外声明“可显式开始精调” |
| 7. 显式启动 | 接收新的 TARGET START，再检查本次面有效、目标样本资格及全部原门控；不因 SELECT 完成自动启动 | 进入原目标等待/精调链 |
| 8. 面内闭环 | 只消费属于本次绑定的新鲜新帧；局部比例命令→局部限速→基座 XYZ→既有 IK/CAN/关节控制 | 对准后走原确认与人工许可 |

忙时拒绝新的、重复或冲突的切面业务，不能排队到以后偷偷执行。若旧精调还在运行，应先完成显式停止和相应确认再接受新选面；不得把 SELECT 变成隐式中断当前任务的快捷键。相同 SEQ、相同载荷的合法重发继续按原去重规则重放既有应答，不重复运动、不重新建面、不延长期限；SEQ 冲突拒绝。

同一视图再次选择也不能直接复活旧面/旧目标资格。新的有效选择应重新取得相应到位和绑定条件；真正的命令重发则保持幂等。历史应答可以留作查询/重发证据，但历史 ready 不等于当前仍可启动。

**待确认：** 到位稳定判据的采样跨度、角度变化容差及超时预算。复用现有反馈/停止确认能力并补齐有限时间核验，不能把 `robot_scan_verify_pose(view)` 的一次角度吻合当作物理零速度证明。该函数会拒绝活动 capture，所以核验要安排在执行链终结之后。接受 ACK 只表示请求被接收；现有 ABORT 停止确认合同继续独立有效，不能被 SELECT 完成消息替代。

`robot_target_start_at_current_pose()` 当前会清 `has_vision`，工作流还抑制与启动同轮的视觉输入。建议保留这层防旧帧行为：工作流先保存“本次新样本预检通过”的有时限资格，显式 START 通过后目标模块仍等下一张匹配的新帧才发速度。不能为了“启动前已经收到一张”而把旧缓存强灌进 ALIGN。预检资格在超时、换目标、移动、停止或故障时立即失效。

### 5.1 状态与旧正视资格如何交接

1. 扫描 HOME→正视尚未完成时，仍用原 `FLOW_SCAN_ACTIVE/FLOW_SCAN_READY` 与正视核验，不允许插入新 SELECT。
2. 最终正视就绪后接受新选面时，立即消费其“当前仍在正视”的资格；扫描历史 ID/完成记录可保留用于查询，但不能继续声称 `FRONT_OBSERVE_READY` 或沿用旧 flags 放行。
3. 新选面执行结果必须匹配当前选择；进入所选面 ready 前核验 `robot_scan_verify_pose(selected_view_id)` 或等价真实反馈条件，并建立工作面。旧 `capture_done_mask` 不能被强行置满来兼容扫描新链。
4. 对 `workflow_target_start_error()`、`workflow_scan_step()`、扫描 QUERY、快照、重发缓存和 Jetson/UI ready 状态一起处理。正确做法是“旧正视阶段保持原检查，新工作面阶段检查所选面”，不是简单删除 front-only 门控。
5. 精调开始后会离开固定配方点，消费“固定观察位 ready”，以活动工作面、实际运动反馈及原伺服约束管理。不能在精调中继续要求所有关节始终等于观察位配方，也不能容许其他运动悄悄改变工作面。

### 5.2 样本身份、旧数据和迟到帧

清旧数据的语义是 `valid=false / has_vision=false`、撤销旧帧计数资格，**不是填 `(0,0)` 并当作已对准**。应覆盖串口解析层最新值、工作流观测、目标模块缓存和 Jetson 尚未发送的检测结果；同时处理半帧、排队字节、异步识别回调与迟到 ready。

**待确认：新旧视觉帧归属合同。** 首版必须能区分本次业务/目标、所选视图、选面代次和样本新旧顺序，并在到位初始化后建立采集屏障。确认方式是检查双端实际报文、采集时间点和队列/回调行为，冻结可回放的正负例：上一次目标、上一次选面、旧采集后迟到、重复、乱序、重启和 SEQ 回绕均不能被当作本次新样本。

当前旧视觉报文没有完整目标/选面绑定。MCU 的 `received_ms` 只能说明何时接收，不能证明图像是在本次到位后采集；单字节 SEQ 及现有去重也不能独自证明目标身份。不能只清一次缓存，然后接受“下一包”就声称解决了迟到帧。

优先复用现有 CAPTURE SELECT、视图号和状态。若旧字段不足以表达上述必要身份，则采用**最小协议扩展，待 MCU 与 Jetson 双方冻结**：例如在双方已绑定上下文的基础上，以一个可区分重启/选面代次的上下文标识加样本编号引用目标与视图。具体字段、TYPE/LEN、错误码、编号回绕/失效规则、最大载荷和兼容方式都尚未确定，本文不自拟线上字节，也不声称旧报文已含这些字段。没有等价且可验证的身份保证前，不能把多视图正式精调判为实现完成。

收到不匹配、旧代次、重复或乱序帧时丢弃并记录原因，不刷新视觉有效期、不增加稳定/确认计数、不恢复输出。当前同一目标不可见或身份不确定时保持关闭输出并等待/停止，不自动选另一颗。双端断链、重启或取消后，旧回调及迟到状态不能重新激活按钮、运动或许可。

## 6. 第二部分：视觉闭环内部连续粗精过渡

### 6.1 保留什么，替换什么

当前比例项本身会随误差变小而减速；问题是饱和上限在 `e=30 px` 附近从 1.2 突然变成 0.8 mm/s，噪声可能引发反复切档。是否造成可见回摆或耗时增加仍是待比较的现象，不能先认定为已证实根因。

首版建议只替换 `target_update_visual_servo_velocity()` 中基于误差的两档速度上限。保留比例闭环、最终对准阈值、连续新帧确认、原速度/关节约束和所有停止路径。第一部分把命令换到局部二维，第二部分就在该局部二维上生成连续限速，不再另造一条控制链。

**待确认：** 插值下界 `e_f`、上界 `e_c`（px）、精/粗上限 `V_f/V_c`（mm/s）及分量/合速度口径。先以当前 30 px、0.8/1.2 mm/s 两档策略作对比基线；沿用哪些端点须明确记录，不能把新插值区间擅自冻结。新策略不得为追求速度提高原允许上限或放松关节约束。

### 6.2 建议的有界连续限速

一个足够小的候选是用三次平滑插值连接两个上限：

```text
e = max(abs(ex),abs(ey))
t = clamp((e-e_f)/(e_c-e_f), 0, 1)       # 要求 e_c > e_f
s = 3*t*t - 2*t*t*t
V(e) = V_f + (V_c-V_f)*s                # 要求 0 <= V_f <= V_c
w = A_view · [ex,ey]^T                 # 局部二维比例命令
v1 = clamp(w1, -V(e), V(e))
v2 = clamp(w2, -V(e), V(e))
v_B = b1*v1 + b2*v2                    # 再满足原基座/关节边界
```

这是“局部分量上限”候选，与当前逐分量限幅口径最接近。若选择合速度限幅，需要共同缩放并单独核对与旧策略的可比性，不能把 1.2 mm/s 的分量上限直接当作已经批准的合速度上限。

在 `e<=e_f` 时保持精调上限，`e>=e_c` 时保持粗调上限，中间连续过渡；仍由比例项使靠近目标时的实际命令自然降低。无需再叠加复杂自适应增益。参数非法、非有限数或工作面无效时拒绝启动/按原故障路径处理，不能悄悄除零或使用任意默认映射。

本函数消除的是**限速随误差变化的跳变**，不是保证每个时间采样的命令都连续。视觉误差突跳、符号改变或帧间隔变化仍可能造成命令变化，需以日志指标判断实际平滑程度。

### 6.3 命令变化率限制：按需要增加的独立项

命令变化率限制约束相邻命令的变化量，例如 `|Δv| <= a_limit·Δt`，与误差到速度上限的插值解决不同问题。建议先完成连续限速这一最小项；若后续离线回放或无输出联调仍显示帧间命令突变，再决定是否将变化率限制纳入首版。

**待确认：** 是否启用变化率限制、限局部向量还是分量、`a_limit`（mm/s²）、实际 `Δt` 的取法及异常间隔上界。用既有帧周期/反馈日志比较确认，不在本文随意给新数值。若增加，状态绑定本次工作面并从零初始化；不跨视图沿用上一方向的速度。

优先级必须明确：原停止、故障、容差内零速保持和速度硬上限高于平滑器。限速上界收紧与变化率约束冲突时先满足硬限制，不承诺任何情况下都同时满足“慢慢变化”。变化率限制不能成为延迟停止的斜坡。

### 6.4 连续过渡的执行流程

1. 仅在本次面有效、当前同一目标的新鲜新帧到达且原条件通过时计算 `e`。
2. 先检查对准容差；在原 2 px 容差内沿原零速保持与新帧计数路径，不为平滑而继续微动。
3. 容差外计算局部比例命令与 `V(e)`，执行有界限幅；若已明确启用变化率限制，再在允许范围内处理命令变化。
4. 经冻结的工作面映射得到 XYZ，送原伺服积分/IK/关节链；保留基座与关节限制。
5. 无新帧不能伪造样本或刷新 `last_update_ms`。显式视觉无效、超时、停止和故障按原路径零速/退出，不以插值保持旧速度；可继续沿用原有的帧间容忍和超时语义。
6. 切面、换目标、停止、故障、重新启动时复位过渡器及确认计数。恢复必须重新满足本次目标/工作面条件，不能因旧状态自动续跑。

最终 2 px 阈值、连续 3 帧和再确认 2 帧保持当前基线；只有独立讨论并获明确要求时才另改，不能把平滑优化与放宽对准判据绑在一起。

## 7. 两部分衔接与分阶段实施

实施顺序如下；分阶段是为了定位问题，第一部分的门控、身份和停止处理属于该阶段的必需项，不是后补选项。

| 阶段 | 工作与交付 | 本阶段完成条件 |
|---|---|---|
| A. 冻结实现合同 | 就地确认各视图方向来源、像素符号/单位、变换责任、瞄准参考、工作范围、样本身份和状态语义 | 接手者能解释每个量来自哪里；缺项有明确影响和确认办法，无假标定 |
| B. 三视图最小完整链 | 先保留原两档限速，完成选面→到位→建面→作废旧帧→新样本→显式启动；接通 Y；原门控全保留 | 离线能覆盖三视图及异常分支；不得先让侧脸运动、以后再补停止与旧帧处理 |
| C. 连续限速 | 在同一局部二维闭环中替换两档上限，保留 B 的所有行为和基线阈值 | 插值有界、连续，停止和新帧确认不回退；变化率限制按对应段落另行确定 |
| D. 后续单独授权的实机验收 | 先关闭实际输出检查方向、到位、局部可达和停止，再比较平滑性；输出相关测试另受原许可与硬件条件约束 | 明确区分离线、构建、烧录、实机运动与输出验收证据；本文不执行这一阶段 |

第二部分始终使用第一部分锁定的工作面；工作面失效必须先停止，不允许平滑器继续输出旧方向。当前文档编写不要求先做新的模型实验，也不要求现在烧录或连接设备。

2. **二维面内到 XYZ：** 含非零 Y 的命令能到达执行积分；`n·v_B` 和累计法向位移残差符合待定数值容差；超时、停止与失败时 XYZ 全归零。限幅不破坏面内约束。
3. **串行与旧状态：** 移动中 SELECT/START 被拒绝；ACK 不放行；只成功 HOME 而未完成视图到位不放行；选面后 QUERY、缓存和 UI 不再显示旧正视 ready。精调中不误用固定配方角检查，也不允许外来运动。
4. **样本归属：** 清旧数据不是零误差；旧目标、旧代次、到位前采集后迟到、乱序、重复及回绕帧不计数；预检通过后超时失效；START 同轮旧帧不灌入目标模块。
5. **原保护回归：** 测距锁存、心跳、安全输入、IK/FK、关节范围/跟踪、人工中止、开始/停止去重与确认继续有效。故障及换面不继承旧输出许可，不自动恢复或 HOME。
6. **平滑函数：** 上下界和边界两侧连续、有界；大/小误差、误差换号、非法参数、长帧间隔可预测；对准容差内直接零速保持，仍需独立 3+2 新帧。若有变化率限制，检查初始化、重置及停止优先级。

**待确认：** 上述正交/法向残差、姿态偏差等离线容差和实机验收阈值。按当前浮点精度、现有 IK/FK 容差及反馈分辨率分别确定，不把纯软件误差容差当成真实机械精度或安全间距。

平滑性比较采用相同目标/视图、误差样本和原门控，记录局部及基座命令的最大变化量/变化率、30 px 附近往返穿越时的命令波动、实际误差与回摆、成功率和对准时间；后续有真实反馈时再比较实际运动。相同输入回放能比较命令平滑，不能独自证明闭环实机更快或更准。

验收主要看粗精切换及命令是否更平滑、原限制和停止是否保持有效；**对准时间缩短不是必须条件**。如果更平滑但略慢，仍可符合用户目标；不能为获得更短耗时放宽原速度、对准或人工许可条件。最大允许波动和可接受耗时变化需在相应比较任务中明确，本文不预填结论。
