# 人脸恒高弧线连续扫描需求与实施规划

日期：2026-10-01

适用工程：`E:\Renesas\RA6M5-Robot\Robot_FreeRTOS - Arm`。

状态：需求已完成主要确认，本文是后续代码改造的规划，不代表扫描功能已经实现或通过上板验证。本次仅新增本文档，不修改固件、原固件说明或正式通信协议。

## 1. 已确认的要求

| 项目 | 用户确认的要求 |
|---|---|
| 相机 | Gemini 305 安装在机械臂末端 |
| 采集方式 | 机械臂运动期间，Jetson 连续采集 RGB 和深度数据，用于构建人脸三维模型 |
| 扫描方向 | 左视图出发，经过正视图，到达右视图 |
| 路径 | 人脸前方的水平弧形路径，保持高度不变 |
| 相机朝向 | 移动过程中同步调整朝向，持续朝向人脸中心 |
| 三个参考姿态 | 先完全沿用当前三视图拍摄姿态，评估能否连续连接，不自行修改旧拍摄点 |
| 后续流程 | 从扫描数据中保留左、正、右代表图；医生仍选择一张视图，沿用现有定靶流程 |
| 扫描结束 | 机械臂在右端保持，Jetson 确认采集数据保存完成后，MCU 才执行回 HOME |
| 安全距离 | 沿用当前固件的 100 mm 阈值，另行标定整条扫描路径的余量 |
| 扫描期保护 | Jetson 持续上报真实距离；过近、测距无效或超时时，MCU 停止并保持 |

单次扫描用时尚未确定。实施方案应支持可调用时，不把当前演示命令的 8 秒上限作为新功能上限；具体默认值和允许范围在几何评估、采集帧率与机械稳定性测试后确定。

“恒高”在本计划中指相机有效成像中心在机械臂基座坐标系中的高度保持不变，而不是只让 `auto` 的 Z 参数不变。允许的实测高度误差需要在验收前标定。当前没有要求必须为数学上的精确圆，但必须验证整段路径在脸前、平滑、恒高且保持有效视野。

## 2. 当前代码与第 9.5 节的对应关系

### 2.1 正式三视图仍是逐点请求

`doc/RA6M5 固件说明.md` 第 9.5 节使用：

```text
CAPTURE_CTRL HOME
  -> GOTO 1，完成后拍左视图
  -> GOTO 2，完成后拍正视图
  -> GOTO 3，完成后拍右视图
  -> HOME
  -> SELECT 1/2/3
```

`APP/robot_workflow.c` 使用 `capture_next_point` 和 `capture_done_mask` 校验顺序。每次 GOTO 只执行一个请求，`CAPTURE_POINT_READY` 表示该点完整配方已经执行成功。

这套接口没有扫描准备、连续运动开始、扫描结束或采集保存确认的语义。不能用一次 `CAPTURE_POINT_READY` 代替扫描开始，也不能连续发送三个 GOTO 就认为已经实现连续扫描。

### 2.2 当前三个参考姿态以代码为准

`APP/robot_capture.c` 中三个视图共用基础位置 `auto 0 -130 -15`，再执行 J1、J4、J5 的绝对旋转。基础位置已经完成时，后续视图可跳过重复 AUTO。

| 参考视图 | J1，下标 0 | J4，下标 3 | J5，下标 4 |
|---|---:|---:|---:|
| 左 | 70° | 330°，连续表示为 -30° | 86° |
| 正 | 90° | 0° | 83° |
| 右 | 115° | 35° | 85° |

J2、J3 不能直接填 HOME 角度，必须取基础位置真实到位后的反馈。后续评估要读取三个实际姿态的完整 J1～J5 角度，不能只用以上三列。

J4 跨越 0/360° 时，轨迹生成应使用连续角度表示，再按现有限位映射；禁止把 330° 到 0° 当成转过 330°。

### 2.3 已有 view_arc 可以参考，但不能直接作为正式扫描

`APP/robot.c` 已有 `ROBOT_VIEW_ARC_EVENT` 和 `robot_send_view_arc_event()`，在 `Middle/robot_cmd.c` 中对应文本命令 `view_arc`。

现有实现的限制：

- 从基础位置进入左端，再用关节空间曲线连续经过三个演示姿态；不是围绕人脸中心规划的相机轨迹。
- 演示参数与正式拍摄姿态不同，例如演示左端 J1=65°，正式左端为 70°；不能用演示参数替换本次指定的参考姿态。
- 使用 10 ms 节点和 800 点静态缓冲，目前扫描时长限制为 4～8 秒。
- 扫描结束主要打印日志，没有供 workflow 消费的独立扫描完成结果和正式扫描状态回传。
- 成功结束也清除 `POSE_VALID`，因此不能直接接回现有定靶启用门控。
- 关节曲线生成时主要对终点做限位映射；新功能需要检查整条路径的关节限位、实际相机位置、朝向和安全距离。

可复用其平滑时间参数、关节速度控制、批量 CAN 反馈和运动中止机制；不直接沿用其全部业务行为。

### 2.4 需要记录的文档差异

当前 `APP/robot_workflow.h` 的安全阈值为 100 mm，撤离参数为 20 mm/步、最多 8 步。固件说明和协议文档仍有 150 mm、最多 5 步的描述。

用户已确认本次扫描按 100 mm 规划。后续需要同步修正文档中的事实描述；本次不自行更改旧流程的撤离参数，也不把扫描保护停止扩展为自动撤离。

## 3. 首先评估几何可行性，再进入代码实现

### 3.1 最少需要的标定数据

1. 左、正、右三个真实到位姿态的 J1～J5 反馈，记录多次到位的差异。
2. 相机相对现有运动学工具坐标系的安装位置和朝向，即 `T_tool_camera`。
3. 固定人脸模型的中心位置、朝向，以及各参考视图的实际相机到脸距离。
4. 本次扫描的有效采集帧率、连续深度有效性，以及患者或模型是否能保持稳定。

相机安装位置尚未给出，当前不能声称这三个姿态已经满足相机恒高或朝向人脸中心。

现有 `robot_kinematics_forward()` 对 J6 按固定框架处理，并排除其运动和位移。相机的安装偏移需要另行建模，不能把工具原点自动当作相机中心，也不能仅凭旧 DH 参数推断相机高度。

### 3.2 评估步骤

使用真实角度进行 FK，并按下式计算相机在基座坐标系中的位姿：

```text
T_base_camera = FK(J1...J5) × T_tool_camera
```

依次检查：

- 三个相机中心是否能落在同一水平面内，偏差是否满足标定后的验收容差。
- 是否存在在脸前、通过三个参考点的平滑弧形路径，且整段距离均保有安全余量。
- 三个参考姿态的光轴是否能朝向同一人脸中心，过渡过程中人脸是否持续处于视野内。
- J1～J5 能否完成位置与朝向约束，不依赖作为夹爪使用的 J6 提供额外转动自由度。
- 路径中间是否经过不可达点、关节限位、明显奇异区、自碰撞区或相机线缆受限区。

检查结果应输出端点、正视参考点、完整采样路径及最不利距离报告。通过三个点本身，不等于整段安全。

### 3.3 可行性分支

| 评估结果 | 后续处理 |
|---|---|
| 当前三个姿态和中间轨迹满足要求 | 冻结扫描配方，进入最小实现 |
| 参考姿态满足要求，简单关节插值不满足 | 只调整中间轨迹，保留三个原始参考姿态，重新验证所有采样点 |
| 三个参考姿态本身无法同时满足恒高、朝向或安全要求 | 先报告冲突和最小调整建议，向用户确认后再决定；不自行改旧视图点 |
| 当前运动学模型或五轴约束无法得到可行路径 | 停止推进正式扫描，记录不可行原因，另行讨论运动学改造 |

当前不能保证“旧三点完全不变”和“相机严格恒高、持续朝向中心”一定可以同时满足。这是第一阶段必须解决的实际问题。

## 4. 建议的最小实现

### 4.1 MCU 与 Jetson 分工

| MCU / RA6M5 | Jetson |
|---|---|
| 执行经验证的固定扫描配方 | 采集 RGB-D、保存数据、构建三维模型 |
| 维护安全距离、心跳、限位、故障与运动许可 | 持续发送心跳和真实距离 |
| 真实到位后回传左端准备完成 | 确认采集通道准备好，再请求扫描开始 |
| 一次连续执行左到右轨迹 | 在运动期间连续采集，不再逐点请求 GOTO |
| 回传运动开始、结束与故障 | 区分运动结束、数据保存完成和模型构建完成 |
| Jetson 确认保存后回 HOME | 提取并保存三个代表视图，声明本次数据已保存 |

MCU 不处理图像、点云拼接或三维重建算法。本文仅约定这些任务与 MCU 的通信边界。

### 4.2 轨迹执行方式

优先在评估阶段生成一条经过验证的关节轨迹配方，由 MCU 以现有 10 ms 控制周期连续执行。配方可以使用经过验证的分段曲线系数或少量控制节点；中间节点处不停止，不执行额外 HOME。

先验证关节曲线经 FK 后确实满足相机的水平弧形与朝向约束，再决定是否需要额外的笛卡尔姿态规划。不能把关节角插值结果直接命名为恒高圆弧。

轨迹时间参数应保证起止平滑，并保证段间位置、速度连续；正视图不是新的起停点。整条扫描使用一个运动任务和一次运动结果，不拼接多个自带终点停止的 AUTO。

长时扫描建议采用按时间在线生成目标节点的方式，使用固定容量上下文，而不是扩大完整轨迹缓冲。必须预先完成全路径检查；在线执行不表示临时绕过路径验证。

仍复用前馈 + P、CAN 反馈和现有运动 generation 中止机制。扫描执行时应检查反馈有效性和跟踪误差，不能忽略控制周期中的失败返回。正式实现需要提供 `NONE/RUNNING/OK/FAILED/ABORTED` 的扫描结果，避免被 AUTO 的结果消费者误取。

开始前和结束后读取真实角度。只有完成终点确认及基于实际角度的 FK 后，才能更新当前位置和位姿有效性；不能仅因为时间走完就宣布右端到位。

### 4.3 三个代表视图

左右端可以在边界保持时选取清晰图像；正视图必须从连续运动的图像窗口中提取，不要求机械臂在中间停止。

中间正视参考点的时间或轨迹进度必须来自实际配方，不默认它恰好位于总用时的 50%。Jetson 可以在该参考点前后选择清晰度更好的帧，但需确认该帧对应姿态与旧正视点的偏差在验收范围内。

代表图的 `point_id=1/2/3` 继续对应原来三个实际拍摄姿态。若代表图与原始姿态差异过大，返回旧 SELECT 点可能看不到同一视野，不能把这项差异留给后续视觉伺服掩盖。

## 5. 控制接口与通信规划

### 5.1 协议外壳与扩展原则

沿用 `A5 5A + VER/TYPE/SEQ/LEN + CRC16/MODBUS`、小端整数和当前串口参数。

为扫描新增独立消息语义，保留旧 `CAPTURE_CTRL GOTO/HOME/SELECT`。不改变原有 `CAPTURE_POINT_READY` 的到位含义，不把多个阶段塞进一个“已完成”标志。

建议新增 `SCAN_CTRL` 和 `SCAN_STATUS`。消息 TYPE 可考虑当前未占用的 `0x07` 和 `0x82`；这两个值仅是规划建议，尚未加入代码或正式协议，实施前须完成双方对接表冻结。

`SCAN_CTRL` 至少包含：动作、固化配方编号、本次扫描编号，以及 START 使用的扫描用时。Jetson 不通过该接口下发任意坐标或关节角。

`SCAN_STATUS` 至少包含：扫描编号、业务阶段、错误码及 MCU 单调时间。一个会话跨多个请求时，扫描编号关联整次采集，SEQ 关联各个具体命令。

### 5.2 推荐的握手流程

| 顺序 | Jetson 发送 / 动作 | RA6M5 行为与回传 | 通过条件 |
|---:|---|---|---|
| 1 | 现有 WORKFLOW START、心跳、测距 | HOME、公共测距、原有安全锁存 | 初始距离和原有流程许可通过 |
| 2 | `SCAN_CTRL PREPARE` | ACK；准备基础位置并移动到左端；回 `SCAN_READY` | 左端真实到位且扫描路径校验通过 |
| 3 | 开启连续采集并确认帧流正常 | 左端保持、激光关闭，等待 START | Jetson 已有可用 RGB-D 数据 |
| 4 | `SCAN_CTRL START` | ACK；启动完整轨迹；回 `SCAN_STARTED` | 左端起始姿态、安全距离和心跳有效 |
| 5 | 周期心跳与 SAFE_DISTANCE，持续采集 | 连续扫描；回传必要进度 / 参考点信息 | 途中无安全或控制故障 |
| 6 | 继续接收尾部图像 | 右端确认成功后回 `SCAN_MOTION_DONE`，保持当前位置 | 真实终点确认成功 |
| 7 | 保存原始采集数据和三张代表图 | 右端保持，不自动返回 | Jetson 完成持久化保存 |
| 8 | `SCAN_CTRL DATA_SAVED_RETURN_HOME` | ACK；执行 HOME；PASS 后回 `SCAN_HOME_READY` | 扫描编号匹配，数据保存及三张代表图均被确认 |
| 9 | 医生选择图像，发送原有 SELECT | 进入原有选中视图到位和定靶流程 | 新扫描采集有效，HOME 完成 |

`DATA_SAVED_RETURN_HOME` 表示原始数据和代表图已经保存，不代表三维模型已经构建成功。Jetson 无需让机械臂一直等待三维重建计算结束。

扫描期间，取消和异常保持仍使用现有 `WORKFLOW ABORT_HOLD` 语义。保存超时则保持并上报，不自动回 HOME，也不自动判定采集成功。

### 5.3 SEQ、重发与完成语义

- ACK 只表示命令接受，不代表运动开始或到位。
- READY 使用 PREPARE 的 SEQ；STARTED、扫描进度和 MOTION_DONE 使用 START 的 SEQ；HOME_READY 使用保存返回请求的 SEQ。
- 同一请求的重发使用相同 TYPE、SEQ 和 payload，不能重复执行扫描。
- 当前控制命令去重缓存为 3000 ms；新扫描可能明显更长，需要保持活动扫描请求的关联记录直到终态，不能仅依赖旧缓存有效期。
- 忙时收到新编号 START 必须拒绝；旧会话的保存确认不能使新会话回 HOME。
- 中止后旧请求、旧运动结果和旧遥测全部失效，不能恢复自动运动。
- 重要阶段应可重发或查询。不能因一次 STARTED 或 MOTION_DONE 状态帧丢失，让双方进入永久等待。
- 暂存轨迹进度不是实际相机到位证据，扫描中断也不得生成成功的保存/完成状态。

### 5.4 帧与运动数据关联

最小版本提供扫描起止事件、MCU 时间和正视参考点事件，Jetson 在 START 前启动帧缓存，避免 STARTED 回传延迟导致漏掉起始数据。

若后续三维重建需要机械臂提供位姿初值，再增加有时间戳的真实 J1～J5 反馈或 FK 位姿遥测。命令目标与反馈值需要明确区分；有串口时间戳不等于与相机曝光硬同步。

若位姿将直接用于三维坐标拼接，必须另行验证 MCU 与 Jetson 时钟对应、相机帧时间含义和 `T_tool_camera`。第一版不宣称仅凭进度百分比即可精准配准点云。

所有遥测应限频、非阻塞，不在 10 ms 控制任务中等待 UART 发完。安全处理和 ACK / 终态回传优先于可丢弃的进度数据。

## 6. 扫描期间的安全规则

扫描 PREPARE、左端等待、RUNNING 和右端保存等待期间，激光始终关闭，定靶子状态机不能接管输出。P000 按下不启动扫描，也不能打开激光。

扫描阶段的距离门控采用实时输入，而不是仅依赖之前的 `distance_safe_latched`：

- START 前，需要收到新鲜、有效、达到 100 mm 阈值的真实测距。
- 扫描中距离低于 100 mm，立即中止运动并保持。
- 收到 `valid=0`，立即中止并保持，不把旧的安全距离当作当前值。
- 连续没有新测距超过超时阈值时，中止并保持；超时参数根据实际距离帧间隔标定，建议初始讨论值为 500 ms，尚未冻结。
- 100 mm 是停止门限，不是路径设计距离。标定路径必须留出测量误差、通信延迟和机械停止距离对应的余量。
- 相机深度原点与最靠近脸部的设备部位之间的偏移必须计入标定，不能只看镜头中心距离。
- 心跳超时、限位、控制反馈失败和运动中止继续服从原有 workflow 安全优先级。
- 相同旧距离帧的重发不能刷新数据新鲜度。SEQ 只能用于去重和关联，接收时间不能证明深度采样时间；Jetson 必须发送新采样。

现有 SAFE_DISTANCE 没有源采样时间戳。第一版需把“新帧对应新测量、不得缓存重放”写入对接契约；若不能保证，应增加带采样编号/时间的新测距消息后再启用正式扫描。

扫描故障后不自动沿弧线继续、不自动退让、不自动回 HOME。进入既有故障保持流程，清除扫描有效标志，等待人工处理。

扫描回 HOME 的路线也需要验证，不能因为终点已安全就默认软复位途经区域安全。返回期间是否可以持续获得人脸距离，应在标定中验证；若离开有效测距视野，要依赖已验证的返回路径，而不能把无效深度误当作安全证据。

## 7. 分任务实施与逐项审查

## 8. 最终验收与尚待测量的参数

| 验收项 | 验收依据 |
|---|---|
| 左到右连续运动 | 录像和反馈日志中没有正视点停顿，没有中途 HOME 或分段 AUTO 停止 |
| 相机恒高 | 标定后的相机位姿与实测高度变化均达到约定容差 |
| 朝向人脸中心 | 各段都保持有效人脸视野，光轴偏差在标定范围内 |
| 路径安全 | 整段路径和返回路线经过验证，最不利距离有停止余量 |
| 实时安全保护 | 距离过近、无效或超时时停止并保持，P801 始终关闭 |
| 终点真实确认 | 右端完成回传以实际反馈和到位确认成功为依据 |
| 保存握手 | 未收到合法保存确认时不自动回 HOME；收到后真实 HOME 成功才回传 |
| 三视图衔接 | 三张代表图已保存，原 SELECT 能回到匹配视野并进入现有定靶流程 |
| 通信幂等 | 重发不重复运动，过期会话不触发当前动作，异常后不自动续跑 |
| 三维模型 | Jetson 使用实际采集数据独立验收；MCU 扫描成功不等于模型质量合格 |

实施前仍需要确定：相机安装变换、完整三姿态反馈、人脸中心参考、扫描默认用时、恒高/朝向/跟踪误差容差，以及连续测距的实际采样周期。这些都是标定或对接输入，不应从旧演示参数中猜测。

后续代码改造从任务 1 开始。当前仅确认了功能样式和安全行为，还没有证明旧三个姿态能组成满足全部约束的扫描轨迹。
