# Jetson全局软件复位接口对接

日期：2026-10-13。接口修订：`GLOBAL_SOFT_RESET_20261013`。

本地MCU源码已实现，新增工作流action04；不是双方已部署的证明。Jetson须按本文接入并人工核对板上固件。帧版本仍为01，没有自动能力协商；旧固件会拒绝04。

## 1. 接口作用

```text
用户显式点击“全局软件复位”
  -> Jetson停止旧流程自动推进，发一次复位请求
  -> MCU关闭输出、停止视觉伺服、取消采集/扫描和旧运动
  -> 等原停止应答、执行器退出及新五轴反馈稳定确认
  -> 软件回HOME
  -> 新五轴校验HOME
  -> 清本轮流程资格，进入IDLE，回复位完成
```

这是**会带动机械臂回HOME的操作**，不是RA6M5重启、驱动器恢复出厂或依赖限位开关的硬回零。不得用来绕过急停或代替硬件停止。固定模型、路径和线缆需现场确认；任意姿态的返回路径不因接口存在就已安全验收。

它可以从IDLE、测距、撤离、采集、扫描、最终正视、定靶及故障/中止保持发起。已有停止事务尚未确认时拒绝BUSY；已有复位未结束时新SEQ也拒绝BUSY。同SEQ重发只回原记录，不重复执行。故障保持下仍须重新通过停止检查才能运动。

## 2. 请求字节表

Jetson → MCU：`TYPE=06 / LEN=1 / payload[0]=04`。

| 字段 | 含义 |
| --- | --- |
| VER | 01，沿用原帧格式 |
| TYPE | 06，WORKFLOW_CTRL |
| SEQ | 新的非零请求编号，01~FF |
| LEN | 01 |
| payload偏移0 | 04，GLOBAL_SOFT_RESET |
| CRC16 | 原MODBUS算法，覆盖VER到payload，低字节先发 |

旧动作不改：01开始测距、02正常结束回HOME、03中止保持。**02不是全局复位，03不会自动HOME。** 请求04不带scan_id/目标坐标/医生许可，也不更新心跳。

## 3. 应答和成功条件

MCU → Jetson：仍为`TYPE=81 / LEN=3`：

| payload偏移 | 字段 |
| ---: | --- |
| 0 | event |
| 1 | value |
| 2 | error |

所有下表应答必须匹配本次复位SEQ：

| payload | 解释 | Jetson行为 |
| --- | --- | --- |
| 21 01 00 | COMMAND_ACK接受 | 进入复位等待；不是停稳或HOME完成 |
| 21 00 xx | 拒绝及错误原因 | 不宣称执行成功，不自动换SEQ继续 |
| 20 05 00 | RETURN_HOME_DONE | 本次全局复位完成，HOME已验证、流程IDLE、输出关闭 |
| 20 07 xx | WORKFLOW_FAULT_HOLD | 复位失败或被取消，不恢复旧流程 |

复用05完成值，但以原请求action04和本次SEQ关联；旧action02、其他SEQ、82扫描完成/HOME_READY不能替代本次完成。

停止确认在MCU内部完成，没有为04发送中间`20 06 00`。独立ABORT请求03仍按原合同等待同SEQ的`20 06 00`，不要改变旧停止处理。

| 错误 | 本接口中的常见原因 |
| --- | --- |
| 03 | 非法LEN、SEQ或参数 |
| 04 | HOME结果后新五轴校验不通过 |
| 05 | 已有停止/复位待完成、接收清理边界或应答缓存忙 |
| 06 | 停止未确认，或HOME命令入队失败 |
| 07 | 心跳无效/失效，禁止返回运动 |
| 08 | 原急停/限位等安全故障 |
| 0B | 软件回HOME失败或45秒超时 |
| 0D | 受保护的相同TYPE/SEQ改了payload |
| 0F | 新ABORT取消复位，或回HOME执行被中止 |

编号复用原定义，不新增错误码。ACK接受后仍可能失败；失败关输出保持，不自动再次复位、继续扫描或进入定靶。

## 4. 重发、预算与取消

- 接受ACK等待300毫秒，最多额外重发3次；重发同TYPE/SEQ/payload/CRC，不创建新复位。
- 接受后保持独立心跳，建议每200毫秒。可以每秒有界重发原复位帧以重取接受/终态记录，但不是发送新动作；从首次发送起总等待最多52秒，不因重发/ACK续期。
- MCU停止确认最多2秒；通过后HOME最多45秒。MCU不会在停止未确认时开始HOME。
- 活动复位记录不按旧3秒缓存过期；终态记录从完成/失败起保留60秒，期间不重复运动。该SEQ在TYPE06下至少保留到终态后60秒；不能复用它做START/HOME/ABORT。
- 记录有界，复位缓存会保留一个槽供新ABORT使用；资源忙返回05，不靠无限改SEQ重试。60秒外不保证重放，禁止自动补发过期请求。
- 任一阶段收到新03 ABORT，会取消复位并停止保持，不自动HOME。先清旧复位事务，再按ABORT自己的SEQ等待停止完成。
- 发送失败或总等待超时：清复位资格，优先发已有ABORT并等待停止完成；无法确认时显示“停止未确认”、停心跳、锁住自动启动，现场处理，不宣称已停稳或已HOME。
- 停止/HOME/确认过程中故障锁保持；只有一次成功复位回IDLE，或原显式恢复机制，才允许后续新流程。恢复心跳和迟到成功不自动续跑。

## 5. Jetson界面/控制层接入

1. 点击前提示该动作会回HOME，由现场人员确认路径可用。界面进入“复位中”，关闭选痣、扫描、定靶和输出资格。
2. **发送前**终止旧扫描/定靶调度、PHOTO事务、旧重发及延迟回调，建立独立RESET事务，再经统一TX锁发送04。心跳保持，不能和旧推进并行。
3. MCU会主动取消旧扫描，可能在04的ACK之前收到旧轮`82 TERMINATED/error0F`、关输出或旧请求拒绝。这些可关联的取消通知是预期清理，不要因此自动发ABORT取消正在进行的复位；也不能恢复旧扫描。
4. 不能一律忽略错误：新的FE异步故障、匹配复位SEQ的失败、链路失效或用户主动停止仍按安全路径处理。旧包和本次复位应分别关联、记录原始字节。
5. 只有匹配复位SEQ的`81/20 05 00`才能显示“复位完成”；解除等待后仍无测距锁存、无选中目标、无定靶或输出许可。下一轮须用户显式START并重新测距。
6. 用户ABORT后，后续04的成功/失败包不得替代03停止完成，也不得解除取消锁。重连、Qt切页或超时不能自动补发旧复位。

MCU成功后清本轮距离/视图/采集掩码、采集执行状态、定靶缓存及扫描上下文，保留扫描ID高水位，防止旧scan_id复用。不清电机零位、关节方向、FK/DH、通信参数或原安全门；不重启芯片。
