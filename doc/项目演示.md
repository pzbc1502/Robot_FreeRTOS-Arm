# 项目演示：固定扫描替换三视图采集，沿用视觉打靶

更新日期：2026-10-09。
适用工程：`E:\Renesas\RA6M5-Robot\Robot_FreeRTOS - Arm`。
适用对象：Jetson / Qt 队友、RA6M5 开发者和双方使用的 AI 编程助手。

**本次业务范围已经明确：把原三视图逐点拍摄替换成固定路线扫描；右扫正常结束后，MCU 自行完成 HOME → 固定正视观察位，并通知 Jetson 最终到位。随后数字人选痣、复核所选同一颗，再用原视觉状态机对准。不是新增真实三维坐标自动到靶系统。**

本文件说明用户要什么及双方各自做什么，不是已经实现的功能清单，也不是可直接发送的字节协议。不得据此自动操作机械臂或解除输出禁用。

## 9. 项目流程与实现边界

### 9.1 先统一六个概念

| 说法 | 本次准确含义 | 不允许推导成 |
| --- | --- | --- |
| 单 Gemini 305 | 一台固定在机械臂末端的双目相机提供 RGB / 对齐 Depth | MCU 直接处理图像或负责三维重建 |
| 扫描一圈 | 按正式配方走左到正、正到右两段，正视中间停稳保存 | 绕头 360°、严格圆弧、恒高或每帧鼻尖精确居中 |
| 数字人 | 展示已有本地 GLB 人脸模型和可对应的目标标记 | 每轮必须重新生成真实人脸网格 |
| 选择一颗痣 | Jetson 记住操作者选中的具体目标，后续在新画面中复核 | 把候选编号当作关节角、观察姿态编号或基座 XYZ |
| 打靶前机械臂伸出 | 扫描正常结束后，MCU 从 HOME 自动进入固定正式正视观察位，先到位再选痣 | 等 Jetson 选痣后才伸出，或按某颗痣的三维表面点规划任意接近姿态 |
| 进入打痣状态机 | 正视真实到位后，沿用实时像素误差、视觉对准及输出联锁 | 到位就开光，或者收到 ACK 就认为对准完成 |

**“到固定正视位”和“对准所选痣”是两个不同动作。**前者由固定机械臂配方实现；后者由 Jetson 识别和 MCU 视觉伺服完成。

本次不要求 Jetson 告诉 MCU 痣的基座三维坐标。MCU 内部原有 FK / IK 或关节控制仍按原运动实现使用，不能误解为完全不需要运动学，也不能反过来要求 Jetson 必须上传三维靶点。

### 9.2 本次改什么、保留什么、不做什么

| 分类 | 明确范围 |
| --- | --- |
| 必须改 | 三视图逐点采集改为两段扫描；正视真实停稳和保存确认；右端、HOME、最终正视到位分别表达；替换旧三点采集门控 |
| 必须衔接 | 右扫正常结束 → MCU 自动 HOME → MCU 自动固定正视 → 最终到位通知 → 数字人选痣及复核 → 原定靶状态机 |
| Jetson 必须保证 | 独立心跳；正视新图实际保存；记录所选目标；当前画面同一颗复核；新鲜视觉误差和无效状态 |
| 可以保留 / 增加 | 扫描视频、途中图像、本地模型展示、候选列表、目标身份标识和日志 |
| 原规则保留 | 原开始 / 测距 / 撤离 / HOME、视觉伺服、P000、故障保持、限位、心跳、输出期间冻结及输出关闭条件 |
| 本次不做 | 痣的基座 XYZ 暂存和自动到靶、任意模型点回访、目标法向 / 6D 接近规划 |
| 不作为固定扫描技术前置 | 手眼安装矩阵、逐帧 FK 遥测、曝光时间同步、视觉里程计、多视角坐标融合 |
| 不擅自改 | FK / DH、候选 J1 映射、电机正方向、观察配方、视觉参数、安全距离和硬件输出上限 |

固定配方不需要先验收“相机到机械臂的三维坐标链”，但**仍需验证固定路径、工作距离、相机视野和激光瞄准参考**。这些实际条件不能因简化方案而取消。

若以后另做三维坐标自动到靶，应单独立项、确认接口和标定，不能悄悄加进本次扫描改造。

### 9.3 唯一主流程

```text
1. 主界面：操作者点击开始
2. 原开始流程：必要复位、伸展至公共测距位
3. 测距位真实到位，Jetson 提供新测距，MCU 按原规则放行
4. Jetson 请求扫描，MCU 准备正式左视起点
5. 第一段：左视 -> 正视
6. 正视真实停稳并保持，MCU 通知拍照就绪
7. Jetson 获取新图、实际保存，回传本轮保存成功
8. MCU 接受确认后执行第二段：正视 -> 右视
9. 右端真实停稳，MCU 报告扫描运动完成
10. MCU 自动返回 HOME，校验真实到位；可报告 HOME 进度
11. MCU 不等待 Jetson 新命令，自动执行固定正式正视配方
12. 固定正视真实到位并停稳，MCU 保持、输出关闭，通知 FRONT_OBSERVE_READY
13. Jetson 核对本轮最终到位及候选可用性，开放数字人选痣
14. Jetson 在此时的新画面中复核所选同一颗痣
15. 按原握手启动打痣状态机，等 TARGET_READY
16. Jetson 连续发送所选目标的新鲜像素误差
17. MCU 视觉伺服，满足原稳定对准条件
18. 操作者复核；P000 及双方已确认的其他输出许可满足
19. MCU 按原安全规则输出，输出时机械臂冻结
20. 松开 / 结束 / 异常时关闭输出
21. 正常完成由明确返回请求回 HOME；异常停止保持，不自动 HOME
```

第 10 步 HOME 是扫描后的中间运动节点，不是整轮点痣结束，也不是等待选痣的位置。第 11 步是 MCU 自动进入同一固定正视配方，不按痣的坐标规划；第 12 步完成后才允许进入可执行的选痣阶段。

右端 → HOME → 固定正视属于同一次扫描请求内的自动业务链。Jetson 不再发送额外 HOME、GOTO 或 SELECT 来推进这三步，也不需要对中间到位通知逐步确认。独立心跳和安全中止始终有效；保存失败、取消、故障或超时不能自动继续右扫、回 HOME 或伸出到正视。

选择下一颗必须先确认上一颗输出关闭及定靶停止，再建立新的目标选择。首版不自动连续发射所有候选。若下一颗的起始位置不是 HOME，应先明确复位 / 返回安排及已验证路径，不能自行从上一次修正后的姿态跳入新流程。

### 9.4 固定姿态来源：不要混用另一套点位

采用当前 `APP/robot_capture.c` 正式 CAPTURE_CTRL 配方，基础位置 `auto 0 -130 -15`。

| 姿态 | J1 | J4 配方 | J4 等价限位域 | J5 |
| --- | ---: | ---: | ---: | ---: |
| 左视 | 70° | 330° | -30° | 86° |
| 正视 | 90° | 0° | 0° | 83° |
| 右视 | 115° | 35° | 35° | 85° |

这是代码配方来源说明，不是现场执行脚本。J2 / J3 由基础定位结果确定，不能用 HOME 角度代填；完整五轴反馈仍须检查。

打靶初始位置固定为正式正视配方。若内部复用 `SELECT point_id=2` 的执行器，2 表示正视姿态，**不表示第二颗痣**。

最终正视到位后才选择目标；首次选择不同痣都使用已到位的同一正视位，不产生新的伸出运动：

```text
扫后自动 HOME -> 自动固定正视到位 -> 选择 R01 -> 新画面复核 R01 -> 视觉对准
扫后自动 HOME -> 自动固定正视到位 -> 选择 R07 -> 新画面复核 R07 -> 视觉对准
扫后自动 HOME -> 自动固定正视到位 -> 选择 R12 -> 新画面复核 R12 -> 视觉对准
```

HOME、公共测距位、扫描正视位以及视觉修正后的最终位置不可混为一谈。PC 旧拍摄点位、标定采样角度和正式配方也不可混用。

正式配方只是当前基准；换装相机后的中间路径、工作距离、线缆及视野仍需实测。发现不合适先报告，由用户确认后调整，不在模块中暗改点位。

### 9.5 第一阶段：开始和安全测距，保留原机制

1. 相机预览和页面浏览不自动启动机械臂。
2. 用户开始后使用原 WORKFLOW START_MEASURE，先 ACK，再等真实 MEASURE_POSITION_READY。
3. Jetson 用到位后的新深度按双方现有测距定义提供实测值，MCU 按原阈值及稳定样本规则处理。
4. 过近时沿用原撤离逻辑，每次 RETREAT_STEP_READY 后重新实测，不复用旧深度。
5. DISTANCE_SAFE_LATCHED 只说明本轮测距通过，不证明整条扫描路径安全。
6. 本批不单方新增持续测距动作，不把安全阈值改成点痣工作距离。

相机深度、相机到目标的距离和工具外形的最小净距不是天然同一个量。保留明确的现有定义，工具偏置或外形需要核对时先验证，不能只改名称就声称安全能力升级。

模型 / 底座移动、相机失效或场景不符时重新核查并停止推进。本方案仅用于固定假人头、已验证路径、有人值守和物理急停可用的台架，不用于证明真人治疗安全。

### 9.6 第二阶段：扫描替换原三视图采集

| 阶段 | MCU 行为 | Jetson 行为 | 不允许的行为 |
| --- | --- | --- | --- |
| 扫描准备 | 检查原许可，准备左视并核对五轴真实到位 | 本轮编号、采集 / 保存任务就绪 | 没测距放行就扫描 |
| 左到正 | 第一段平滑运动，输出关闭 | 展示扫描，可记录途中图像 / 视频 | 把动画进度当真实位姿 |
| 正视停稳 | 报告拍照就绪，停止保持 | 丢弃旧缓存，取新图并实际保存 | ACK 到达就拍、未保存回成功 |
| 等待确认 | 非阻塞等本轮保存结果，继续心跳 / 安全处理 | 成功或失败回传；保持独立心跳 | 超时当成功、重发导致重复运动 |
| 正到右 | 接受保存后第二段平滑运动 | 继续展示 / 记录 | 用另一条旧 GOTO 催进度 |
| 右端完成 | 真实停稳，可报告 SCAN_DONE，自动开始正常 HOME | 显示进度，仍禁止执行选痣和定靶 | 把扫描完成当最终正视到位 |
| 正常 HOME | 经验证路径返回，校验真实到位，可报告 HOME_READY，自动继续正视配方 | 等最终正视到位，不发送额外 HOME / SELECT | 等 Jetson 授权才继续，或 HOME 后提前放行 |
| 最终正视 | 完成固定配方和真实停稳检查，报告 FRONT_OBSERVE_READY 并保持 | 核对本轮及候选，开放数字人选痣 | 把中途拍照就绪或历史 HOME 状态当本阶段成功 |

正视中间允许停顿，扫描是**两段内部平滑**，不是从左到右不停顿。本次不要求严格圆弧、恒高、鼻尖精确居中或 360° 环绕。

正视保存确认是第二段的必要条件；途中的每张图、全脸候选去重、三维融合或点云建档**不是 MCU 继续扫描的必要条件**。

如果 Jetson 已有途中识别 / 记录能力，可以保留，但不能把尚未完成的多视角三维算法自动变成扫描硬前置。没有实际拍摄三张新照片，不伪造“三视图已采集”或旧三点掩码。

仅扫过某一区域不证明该区域没有痣；模型显示成功不证明完成真实三维重建。对评委应如实说明“固定机械臂扫描展示 + 预置模型 + 实时视觉复核”。

### 9.7 第三阶段：模型展示和目标选择，主要由 Jetson 完成

Jetson 负责已有 GLB、候选列表、点击选择和目标记录。MCU 不接收人脸网格，不从模型坐标规划运动。

每颗供执行选择的目标至少在 Jetson 侧保留：

| 信息 | 用途 | 是否必须向 MCU 发送三维值 |
| --- | --- | --- |
| 本轮 / 候选标识、显示编号 | 防止点击和跟踪指向另一颗 | 否；必要标识按双方接口传递 |
| 来源图片、局部外观或其他可验证关联 | 正视新画面中复核同一颗 | 否 |
| 图像方向 / 分辨率、当前像素位置 | 正确识别和计算误差 | 否；传当前误差即可 |
| 候选可见性、歧义 / 丢失状态 | 决定可否进入视觉打靶 | 否；通过有效性 / 状态表达 |
| 模型显示标记的对应关系 | 点击模型和列表选同一记录 | 否 |

相机 XYZ、基座 XYZ、逐帧工具矩阵和手眼安装矩阵均不是本次 MCU 打靶必填数据。Jetson 可以自行留存真实深度或三维研究数据，但不能将其变成 MCU 的 TARGET_POSITION 前置条件。

首版可以使用正视停稳照片中可靠识别、且之后可从固定正视位复核的候选，不强制先完成全脸多视角三维建档。

模型上已有预置标记若保留，须区分“预置展示”与“本轮检测”；没有与实际目标的可靠对应，不能作为自动执行目标。不得虚构检测结果，也不得因标记位置漂亮就认为可打靶。

### 9.8 第四阶段：先自动固定正视，后选痣复核

1. 右扫正常完成后，MCU 自行返回 HOME，真实到位后自动进入固定正视观察位。
2. MCU 按已验证的固定配方和原安全门执行；HOME 或正视失败时停止保持，不等待新命令强行继续。
3. 最终正视真实到位并停稳后，MCU 发 FRONT_OBSERVE_READY，关联本轮和最初扫描请求。
4. Jetson 收到有效最终到位状态、且候选可用后，操作者选中目标；Jetson 固定选择，显示编号和来源。选痣绑定不触发新的运动。
5. Jetson 在当前新画面里重新找到并确认所选同一颗，不沿用扫描旧像素。
6. 确认可靠后接原定靶握手；不可靠时输出关闭并等待处理。

**不需要以下顺序：**

```text
选痣 -> 提交基座 XYZ -> POSITION_STAGED
     -> 校验位置 CRC -> 任意目标 IK 接近 -> 到靶
```

**本次需要的顺序是：**

```text
右扫完成 -> MCU 自动 HOME -> MCU 自动固定正视真实到位
         -> 最终到位通知 -> 数字人选痣
         -> Jetson 同一颗复核 -> 原视觉状态机对准
```

目标身份可以传给 MCU 作为关联和日志，或由 Jetson 维护现有选中 / 跟踪逻辑；具体字节由双方冻结。身份记录不是三维定位模块，也不能把 R07 当作观察姿态 7。

### 9.9 第五阶段：视觉状态机完成实际对准

Jetson 处理图像，MCU 处理运动。沿用先启用定靶、等 TARGET_READY、再消费新视觉误差的顺序。

| 步骤 | Jetson | MCU |
| --- | --- | --- |
| 复核 | 确认所选目标在当前图像中可见且无歧义 | 保持固定正视位、输出关闭 |
| 定靶启动 | 原语义 START 请求，等 ACK / 启用 / TARGET_READY | 检查原许可，进入原等待 / 对准状态 |
| 新误差 | 提供当前目标 dcx / dcy / valid | 沿用视觉伺服和稳定帧判断 |
| 对准完成 | 操作者复核当前真实画面 | ALIGN_DONE，不等于开光 |
| 输出 | 持续监测所选目标和当前视觉 | 所有许可满足才输出，输出时不运动 |
| 失效 | 丢失 / 歧义 / 不新鲜给无效，不换另一颗 | 原规则关输出、停止 / 保持 |

在本方案中，机械臂“最终对上哪颗”由实时视觉误差收敛实现，不是由一次三维坐标下发实现。

误差的参考点、图像方向和缩放须按双方确认的定义一致。旧 TYPE=03 不含三维位置，不能擅自改变它的像素语义或偷偷追加字段。激光瞄准参考需要实测验证，但**像素瞄准参考标定不等于相机到机械臂手眼标定**。

相机目前设置为 RGB / 对齐 Depth 848x530、30 FPS；应核对实际处理坐标和可靠目标频率。显示旋转 180° 或缩放不能让控制方向暗中变化。

本次不改视觉增益、速度、误差容差、稳定帧数或超时，也不自动应用候选 J1 映射。方向、震荡或 IK 失败等问题按原控制诊断处理，不能为了展示屏蔽故障。

### 9.10 固定正视方案的明确限制

本方案不是“在任意一颗侧脸痣上都可以自动打靶”。

- 固定正视位必须能看见所选痣，目标需处于已验证的视觉修正范围。
- 侧脸遮挡、识别歧义、两个相近候选无法区分时，不进入输出。
- 不能自动换成最近、最黑、最大或最稳定的另一颗；这些属性不证明是所选目标。
- 不能看到像素误差就无限移动，仍受工作距离、运动限位、姿态有效性和原失败保护约束。
- 不可见目标可以保留展示并标为当前不可执行，或由操作者重新选择正视可复核目标。
- 若以后要回左 / 右观察位打侧脸目标，应另行确认流程和整条路径；首版不自动添加这一分支。

用像素误差不等于不需要实际测距或激光瞄准验证；只是不需要 Jetson 提交痣的三维基座坐标。

### 9.11 输出许可和安全，不随范围简化而删除

本次改造不能取消原 P000、视觉有效性、稳定对准、心跳、限位 / 急停、故障保持、输出冻结或硬上限。

操作者选痣 / 页面确认不直接开启 P801。输出结束或异常应按原硬件和固件条件关闭，正常返回须明确请求，故障不自动 HOME。

目标身份绑定和单次医生许可不改变本章“固定正视 + 视觉对准”定位方式。当前主流程包含医生确认和硬件许可；一次确认只允许一次输出，目标 / 对准失效、换痣、取消、复位、故障或输出结束后撤销，重新输出必须重新确认。**本文件不自动批准队友草案的 1~2000 ms 租期或自动续租。**具体时长、编码和 P000 再武装规则由双方冻结。

医生许可接口未实现或未验收前，不得绕过它执行，也不能声称 Qt 按钮已经构成 MCU 认可的许可。已有且已启用的安全限制不能为完成演示而删除。

Jetson 目前关于 `calibrated=false` / `T_tool_camera=null` 的记录继续如实保留，不伪造安装标定成功；也不直接解除 Gemini 执行禁用。固定扫描不依赖手眼外参，不代表可以单方绕过原禁用门。接入时需区分“未做三维坐标链”与“固定路径 / 像素瞄准 / 安全未验收”，由双方确认哪些条件真正满足后再开放。

- 当前运动 API 在正视 / 右视成功后停止保持，不自行完成照片握手、HOME 或 Qt 放行。

#### 本次需要接入

1. 独立的扫描准备、第一段、正视保存等待、第二段、正常 HOME、自动固定正视及异常保持。
2. 匹配本轮请求、保存确认和重复命令处理；ACK 与真实到位分开。
3. 将旧 `capture_done_mask==0x07` 的三点采集要求替换为新模式自己的完成条件，不伪造旧三次拍照。
4. 右端成功后自动 HOME，HOME 成功后自动执行正式正视配方，不等待 Jetson 的新运动请求。
5. 最终正视真实到位后记录正视标识及有效状态，报告 FRONT_OBSERVE_READY；复用原定靶安全门，不能只写 selected_view_id 或伪造三点掩码放行。启动定靶仍须再次检查反馈、当前阶段和安全条件。
6. 继续使用原视觉 / 输出实现，不为此次改造增加任意 XYZ 目标规划器。

正文描述的是需要实现的业务，当前完整串口 / workflow / HOME / 固定正视衔接尚未完成，不能写成已有上板功能。

### 9.14 通信对齐：业务与字节分别确认

保留 UART、A5 5A 帧、CRC16、旧消息格式和原安全含义。扫描增加必要的本轮启动 / 拍照就绪 / 保存确认 / 右端进度 / HOME 进度 / 最终正视到位 / 异常语义，不据此推导三维坐标模块。

所有新消息编号、字段和状态仍以双方冻结的协议和实际构建为准，本文件中的业务动作名称不是线上 TYPE。

双方旧草案与本次范围按以下规则对齐；不再引用本地已经不存在的队友附件文件名：

| 草案内容 | 本次处理 |
| --- | --- |
| TARGET_POSITION / POSITION_STAGED | 不作为固定正视打靶前置；不传痣基座 XYZ |
| TARGET_SELECT 要求 calibration_id / position_payload_crc32 | 改为最终正视到位后的目标绑定，不产生新的运动，不检查不存在的位置暂存 |
| 85/86 位姿遥测、FK / 手眼验收 | 可留后续研究，不作为固定扫描 / 固定正视的强制能力 |
| 能力 features 必须恰好 0x1F | 需要支持分阶段 / 实际能力协商，不能虚报已完成全部模块 |
| 1~2000 ms 医生许可 | 不是本次用户批准的输出时长；独立确认，不默认套用 |
| 扫描准备 / START / 正视保存 / 正常 HOME | 保留所需握手，增加 MCU 自动固定正视及最终到位通知 |
| HOME_READY 后等待 SELECT / APPROACH_REQUEST | 撤回；HOME 是中间节点，由 MCU 自动推进，不等 Jetson 命令 |

如果保留队友的新协议框架，应同步修改 Jetson 编解码、流程、C 头、manifest、schema CRC 和测试；不能只改 MCU 或只改文字。

本地[通信协议](<Jetson↔RA6M5 通信协议.md>)同步采用本流程，XYZ 备选模式移出本轮。2026-10-09 已冻结并接入扫描字节；目标 / 复核 / 医生许可仍独立对接，不能将扫描接通称为全流程已经完成。

| 交互 | 本轮用途 |
| --- | --- |
| START / ACK | Jetson 启动一轮扫描，ACK 只表示接受 |
| FRONT_PHOTO_READY | 第一段正视停稳，可以取新图保存；旧草案 FRONT_READY 在本业务中统一使用此逻辑名 |
| PHOTO_DONE / ACK / PHOTO_ACCEPTED | Jetson 报告实际保存结果，MCU 接受成功后仅启动一次第二段 |
| SCAN_DONE / HOME_READY | MCU 可发的中间进度；不需要 Jetson 逐步确认，不放行选痣 |
| FRONT_OBSERVE_READY | MCU 已完成扫后 HOME 和自动正视，真实停稳保持；是选痣阶段的运动放行依据 |
| 目标绑定 / 复核 / 定靶启动 | 选痣后不再伸出；确认同一颗后启动原视觉状态机 |

最终到位通知不要求 Jetson 再回一个运动许可。报文丢失时查询状态，MCU 返回匹配本轮的当前快照，不重复 HOME 或伸出；旧轮、取消前或故障前的就绪状态不放行。HOME 到位历史只证明曾经过 HOME，不证明当前正视有效。

最小链路可以不新增实时三维分析归档握手。若 Qt 自己需要等候选识别完成，作为其选择页面门控即可；不得因此要求 MCU 提供真实三维数据。运动完成、图像保存、候选可选、正视到位、视觉对准和输出仍是不同事实。

### 9.16 验收清单和交付顺序

| 顺序 | 验收内容 | 通过证据 |
| --- | --- | --- |
| 1 | 双方按同一范围和字节定义实现 | 修订表、报文正 / 负例及构建版本 |

| 6 | 验证目标不可见、歧义、失效、断链和取消 | 不换目标、不假对准、关输出保持 |

验收应能回答：

- 没有痣的 XYZ 能否完成扫描、HOME、固定正视和像素对准？本方案应当能，但仍需原安全条件。
- 同一个固定正视位能否复核不同的已选目标？只能在目标可见、身份可靠、修正范围内成立。
- 换痣、看不到所选痣或图像失效是否会输出？不应输出。
- ACK 是否会被当作真实到位？不应。
- 扫描完成是否会被当作 HOME 完成或开光许可？不应。
- HOME 完成是否会提前开放执行选痣，或等待 Jetson 再发 SELECT 才去正视？不应。
- 最终到位通知丢失、重复查询或重复保存确认是否会再次 HOME / 伸出？不应。
- 没有手眼矩阵是否被伪称已标定，或为了通过而删除禁用门？不应。
