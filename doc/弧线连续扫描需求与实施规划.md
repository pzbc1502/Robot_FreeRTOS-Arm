## 1. 本次目标与范围

本次以固定扫描替换原三视图逐点采集：机械臂从左视扫描到正视，停稳后拍摄并保存一张照片；收到本轮保存成功确认后，从正视继续扫描到右视。右端真实停稳后，由 MCU 自行返回 HOME，确认后自动进入固定正式正视观察位；最终正视真实到位并停稳后，通知 Jetson 开放数字人选痣。此时选痣不再触发伸出运动，同一颗复核通过后沿用原视觉伺服，再检查医生单次许可和 P000 等安全条件。

正视处允许停顿，因此本次是“两段平滑扫描，中间停稳拍照”，不要求从左到右不停顿。扫后自动进入正视是为等待选痣及实时复核，不增加第二次必需的保存握手；实时复核仍必须使用新画面。

Jetson 已有与比赛人脸模型对应的本地模型，本轮扫描不负责生成新的三维人脸。展示时应明确区分“预置人脸模型展示”和“机械臂扫描演示”，不能将其作为实时三维重建或真实患者定位精度的证明。

### 1.3 2026-10-11 简化后的MCU测距职责

Jetson上传有效原始相机深度D，沿用 `SAFE_DISTANCE=05 / LEN=3`，不扣除5 mm突出量；无效数据如实发送valid=0，不用旧值冒充新实测。MCU保持现有实现，不新增全流程距离保护：

1. 公共测距位到位后，在原测距窗口处理距离；3个不同非零SEQ的有效样本满足D≥100 mm后锁存，初始无效样本清计数，不放行。
2. 初始过近时保留原逐步撤离及到位后重新测距；原次数、位移和等待预算不变。
3. 锁存后，扫描/HOME/自动正视阶段不新增持续深度阈值或缺帧超时；偶尔没有深度或valid=0，不由MCU新增距离中止。
4. 原心跳超时、显式ABORT、CAN反馈、原软件运动边界、运动/业务超时和关输出保持。已修复的ABORT优先接收及同SEQ停止确认继续保留，不回退。

## 3. 固定关节轨迹的最小实现

### 3.1 动作顺序

1. 沿用原开始、HOME、公共测距和安全放行流程。
2. 进入基础位置，再到正式左视姿态；真实反馈满足要求后开始扫描。
3. 第一段从正式左视平滑扫描到正式正视，减速停稳；真实到位后报告拍照就绪并保持。
4. Jetson 拍照保存并回传本轮完成。MCU 接受确认后，启动第二段，从正视平滑扫描到正式右视。
5. 右端减速停稳并核对真实反馈，可报告 SCAN_DONE；MCU 自动衔接正常 HOME。
6. 采用原 HOME 执行方式，右端开始的整段返回路线仍须现场验证；HOME 真实到位后可报告 HOME_READY 进度，立即在业务层衔接正式正视配方，不等待 Jetson 指令。
7. 最终正视真实到位并停稳，记录正视标识和姿态有效状态，报告 FRONT_OBSERVE_READY；保持、输出关闭，等候选选择和同一颗复核。

右端 → HOME → 正视是原扫描请求内的一条自动链，不需要 Qt 再发 HOME / GOTO / SELECT，也不需要对中间通知逐步确认。只在正常成功分支推进；保存失败 / 超时、取消、心跳超时或任一运动失败时停止保持，不继续第二段、返回或伸出。

该动作以五轴关节轨迹实现，不新增相机坐标系下的 FK/IK 弧线求解。相机实际路径是否具有合适的弧形效果、是否持续入镜，以固定模型的整段实测为准。

### 3.2 分段平滑与执行边界

- 使用原工程的平滑运动方法，两段扫描分别平稳起止。第一段到正视速度归零并停稳；第二段仅在保存确认被接受后从静止开始，不要求跨拍照等待保持速度连续。
- 第一段终点和第二段起点采用同一正式正视姿态。等待结束后核对当前反馈，偏离或失效时不能直接从过期状态续扫。
- 正视停顿是明确的业务步骤，不能宣传为左到右不停顿的连续扫描。两段内部仍需平滑，不能用多个不受控跳变的关节命令拼接。
- 返回 HOME 使用原执行方式，并验证从右视开始的整段返回路线，不能因为右视和 HOME 均安全就默认中间运动安全。
- HOME 完成后基础位置缓存应按原执行器规则重建，再完成正视全部步骤；不能只设置 J1/J4/J5 或写一个到位标志冒充完整正视。
- 运动用时依据轨迹长度、保守关节速度/加速度和控制周期确定，参数集中配置；两段扫描、照片等待、HOME 返回和最终正视分别配置有限预算，未指定秒数不等于无限等待。
- 沿用原固定内存约束。现有 `view_arc` 的 800 点/8 秒边界不能成为轨迹截断理由；超出时须分段或采用正确的固定内存执行方案，并核查 RAM 占用。
- 取消或故障必须中止尚未执行的节点，旧任务不能在新流程启动后继续发送运动指令。
- 等待照片保存采用非阻塞业务状态，继续处理心跳、中止和反馈，不能用阻塞等待令原安全检查失去执行机会。

### 3.3 J4 角度表示检查

扫描中的 J4 参考角使用连贯的合法表示：`-30 -> 0 -> 35`。当前角、目标角和到位参考角必须处于一致的角域，保留原软限位及电机逻辑方向。

对已发现的受影响入口，应做最小修复或可靠隔离，检查 `0`、`360`、接近 `360`、`345.54` 及等价负角的反馈情形。不得将 `360 -> 3` 解释成约 -357° 的运动，也不得因反馈归一化而把到位参考与反馈比较成相差一整圈。

该检查属于轨迹执行边界，不要求先修改整套 FK，也不作为此前手眼标定旋转矛盾的结论。现有 PC 测试正常不能代替上述边界测试。

## 4. 新采集流程与原定靶流程衔接

实现边界：下图从原测距准备到 `FRONT_OBSERVE_READY` 的 MCU 扫描链已实现并离线验证；Jetson 实际拍照保存尚待双端验证。最终到位之后的数字人选痣、同一颗复核、医生许可与输出，是确认的后续业务要求，不是本批已接通的功能。

```text
原 START / HOME / 公共测距 / 安全放行
  -> 基础位置及左视真实到位，输出关闭
  -> 第一段：左 -> 正 -> 正视真实到位、停稳并保持
  -> MCU 回传正视拍照就绪
  -> Jetson 拍照并保存 -> 回传本轮采集完成
  -> MCU 接受保存确认，启动第二段：正 -> 右
  -> 右视真实到位并停稳 -> MCU 回传扫描完成
  -> MCU 自动返回 HOME，Qt 仍禁止执行选痣与定靶
  -> HOME 真实到位 -> 可回传 HOME 进度，不等待 Jetson 应答
  -> MCU 自动进入固定正式正视位
  -> 最终正视真实到位、停稳 -> FRONT_OBSERVE_READY
  -> 数字人选痣，目标绑定不产生新的运动
  -> 当前新画面复核所选同一颗 -> 原视觉状态机对准
  -> 医生单次确认 / P000 / 输出联锁 / 结束返回
```

### 4.1 新增阶段与放行条件

| 阶段 | 允许行为 | 放行或退出条件 |
| --- | --- | --- |
| 扫描准备/第一段执行 | MCU 执行到左视及左到正视的动作；禁止 SELECT 和目标启用 | 正视真实到位且停稳，或中止/故障 |
| 正视等待照片确认 | 机械臂保持，Jetson 拍照保存；禁止第二段、SELECT 和目标启用 | 本轮保存完成确认被 MCU 接受，或等待超时/取消 |
| 第二段执行 | MCU 执行正到右扫描；禁止 SELECT 和目标启用 | 右视真实到位且停稳，或中止/故障 |
| 扫描完成、返回 HOME | MCU 自动 HOME；Qt 只更新进度，不开放执行选痣 | HOME 真实到位后自动继续正视，或中止/故障 |
| HOME 后进入正视 | MCU 自动执行正式正视配方；不等待串口 SELECT | 最终正视真实到位并停稳，或中止/故障 |
| 最终正视保持 | 已实现：报告 FRONT_OBSERVE_READY、保持并禁止旧定靶启动；待接入：候选可用后的选痣与目标绑定 | 当前只允许查询、中止及正常结束返回；同一颗复核与定靶启动待后续接口实现 |

代码已使用 `FLOW_SCAN_ACTIVE` / `FLOW_SCAN_READY` 管理新扫描模式；串口最终保持状态为 `0x0B`，事件为 `0x08`。前五阶段和最终保持已经接入，最终保持之后的目标交接尚未接入。上述状态是否在实机正确推进仍须上板验收。

### 4.2 与旧采集门控隔离

现有旧流程通过 `capture_done_mask == 0x07` 和采集 HOME 放行 SELECT。新模式不走这一分支，独立维护本轮保存确认、两段扫描完成、扫后 HOME 已验证和当前最终正视就绪；全部满足且本轮未取消、未故障，才允许首次选痣绑定与后续复核。

不能直接将旧 `capture_done_mask` 设为 `0x07`：本轮没有完成三次停点拍照。正视保持和右端扫描完成都不是 HOME 完成，不能提前发送 `CAPTURE_HOME_READY`。

原 HOME 执行和真实到位语义可以复用，但新模式完成处理须识别阶段及本轮关联，不受旧三点掩码限制，也不能绕过真实 HOME 检查。HOME_VERIFIED 是曾经过 HOME 的事实，不证明当前位置；Qt 必须收到匹配本轮、当前状态有效的 FRONT_OBSERVE_READY，不能只因保存确认、SCAN_DONE 或 HOME_READY 启用执行选痣。

已实现：最终正视经正式 GOTO 执行和五轴反馈校验后进入 `FLOW_SCAN_READY`，不赋值旧 `selected_view_id=2`，也不进入旧 `FLOW_SELECTED_VIEW`。等待保存及最终保持期间每300 ms核对反馈，查询时重新检查当前资格；其他运动或异常不能复用过期到位结果。

待实现：新目标绑定 / 同一颗复核成功后的定靶上下文交接。届时开始视觉伺服后，应按原实时状态检查，不反复要求仍在初始正视角；不能为接通旧 TARGET 而伪造 SELECT 或三张采集完成。旧逐点模式保持原规则，不另写视觉伺服算法。

### 4.3 后续定靶保持原规则

本节是下一阶段的接口与安全要求。现有独立定靶算法保留，但新扫描链尚未接入目标身份与医生许可，不能将“原算法存在”写成“扫描后打靶已完成”。

保存确认、最终正视到位和选痣绑定都不是输出许可。Jetson 必须在当前新画面复核所选同一颗，再按原定靶握手提供新视觉误差；不可见或身份有歧义时给无效，不自动换痣，不沿用扫描旧误差或模型坐标。

医生确认采用单次许可；与 P000、视觉有效性、稳定对准、心跳、限位、故障及输出硬上限同时检查。输出时冻结运动，失效关输出并撤销旧许可，重新输出须重新确认。正常结束仍由明确返回请求推进，故障不自动 HOME。下一颗若需要重新恢复观察位，须确认旧定靶停止及路径，不把本轮首次自动正视通知当永久到位证据。

## 5. 最小通信扩展

扫描 TYPE、action、字段宽度和字节布局已按[通信协议](<Jetson↔RA6M5 通信协议.md>)第 6 章冻结并接入。目标 / 复核 / 医生许可字段仍待共同冻结，不借用旧事件值改变旧消息含义。


| 交互 | 方向 | 必要含义 |
| --- | --- | --- |
| 扫描请求 | Jetson -> MCU | 本轮编号、启动动作；启动固化配方，不传任意关节角或轨迹点 |
| 接受/拒绝 | MCU -> Jetson | ACK 只表示命令接受，不代表到位；状态不允许、忙或反馈异常时拒绝 |
| FRONT_PHOTO_READY | MCU -> Jetson | 扫描中途拍照就绪；关联本轮及启动请求，仅在第一段正视真实停稳后发出 |
| 正视采集完成 | Jetson -> MCU | 关联本轮，表示照片已实际保存；不能以按钮已点击或已收到到位帧代替 |
| 保存确认接受 | MCU -> Jetson | ACK / PHOTO_ACCEPTED 表示本轮保存结果被接受并衔接第二段，不是最终到位或选痣许可 |
| 扫描完成 | MCU -> Jetson | 两段扫描均完成、右端真实停稳；随后正常返回 HOME，Qt 仍禁止选择 |
| HOME_READY | MCU -> Jetson | 可报告扫后 HOME 真实到位进度；MCU 自动继续正视，不放行选痣，不要求应答 |
| FRONT_OBSERVE_READY | MCU -> Jetson | 扫后 HOME 已验证，且当前固定正视真实到位并停稳，保持且输出关闭；最终运动放行依据 |
| 目标绑定 / 复核 / 定靶启动 | Jetson -> MCU，MCU 应答 | 最终到位后选具体痣；绑定不运动，复核通过再启动原视觉控制 |
| 取消/故障 | 双方按原接口处理 | 停止保持、输出关闭、清除新门控，不继续下一段，也不自动回 HOME |

通信要求：

- 现有 payload 上限为 32 字节；本次仅增加编号、动作和状态，不传图像、点云、安装矩阵或逐帧位姿。
- 旧状态消息的长度和字段含义保持兼容，新增关联信息使用双方冻结的新布局，不能直接塞入旧字段。
- SEQ 关联具体请求，本轮编号关联整个演示与拍照确认；同时遵守旧收发端的序号规则。
- 长动作的活动请求必须持续保留关联，不仅依赖旧 3 秒去重窗口；重发不能重复运动。
- 拍照就绪、确认结果和最终到位支持幂等重放或只读查询；SCAN_DONE / HOME_READY 可作为进度报告，不作为链路等待点。保存确认重发不得再次执行右扫、HOME 或伸出。
- MCU 接受确认后可能已进入第二段。若确认 ACK 丢失，重复确认只返回对应结果，不能要求机械臂重新回正视拍照。
- 中途拍照就绪与最终观察位就绪必须使用不同事件；不能沿用同一个 FRONT_READY 让 Qt 猜阶段。最终通知关联原扫描请求，而不是之后才建立的目标会话。
- 最终通知不要求 Jetson 再给运动许可；丢失时 Qt 查询当前状态，不重启扫描或重发 HOME / SELECT。查询只返回事实，不恢复运动。
- 迟到、错误编号、取消或复位前的保存及到位消息不放行。最终就绪若已因定靶运动或异常失效，查询不能把历史成功重放成当前就绪。
- ACK、两段运动、照片保存、HOME 返回和自动正视分别配置有限超时；Jetson 完整等待预算覆盖所有阶段，不能收到 SCAN_DONE 就结束计时或把全部超时统一改长。
