# 固定弧线扫描演示需求与实施规划

更新日期：2026-10-09。

适用工程：`E:\Renesas\RA6M5-Robot\Robot_FreeRTOS - Arm`。

状态：用户已确认采用“两段扫描、正视停稳拍照、保存确认后继续右视、扫描结束回 HOME”的流程。2026-10-09 已实现独立的两段扫描运动接口；通信握手、比赛流程及打靶衔接仍在讨论，暂不接入。当前 Qt 入口仍不会启动新扫描。本次未烧录或操作机械臂，整段实物路径尚未验收。

## 1. 本次目标与范围

本次只改造原比赛流程的采集环节：机械臂从左视扫描到正视，停稳后拍摄并保存一张照片；收到本轮保存完成确认后，从正视继续扫描到右视。右端停稳后报告扫描完成，再返回 HOME；HOME 真实到位后，才进入原观察姿态选择和定靶流程。

正视处允许停顿，因此本次是“两段平滑扫描，中间停稳拍照”，不再要求从左到右不停顿。扫描结束后不返回正视补拍照片。

Jetson 已有与比赛人脸模型对应的本地模型，本轮扫描不负责生成新的三维人脸。展示时应明确区分“预置人脸模型展示”和“机械臂扫描演示”，不能将其作为实时三维重建或真实患者定位精度的证明。

### 1.1 已确认的要求


| 项目       | 本次要求                                                                             |
| ------------ | -------------------------------------------------------------------------------------- |
| 模型与摆放 | 使用固定人脸模型；相对机械臂的位置和距离基本固定，由现场人员确保在已验证范围内       |
| 扫描动作 | 左视到正视为第一段；正视停稳拍照并等待保存确认；正视到右视为第二段 |
| 几何要求   | 不要求严格圆弧、恒高或鼻尖精确居中；允许高度和朝向变化，尽量保持相关人脸区域有效入镜 |
| 姿态依据   | 先采用当前正式`CAPTURE_CTRL` 配方，不混用 PC 旧配方或标定采样姿态                    |
| 用时       | 没有指定扫描秒数，以平滑、安全、完成为准；仍配置有限的运动和等待超时                 |
| 启动入口   | Jetson 原“采集三视图”入口启动；PC 上位机只用于模拟调试                             |
| 扫描结束 | 右端停稳后报告扫描完成，再返回 HOME；HOME 真实到位后才允许选视图 |
| 拍照与确认 | MCU 报告正视真实到位，Jetson 拍照保存并回传完成；MCU 接受本轮确认后只放行第二段，不直接放行选视图 |
| 后续定靶   | 选择左/正/右观察姿态，到位后沿用原实时视觉复核、对准、P000、输出和结束返回流程       |

本轮不采集三张新视图照片。后续“选视图”在 MCU 侧表示选择三个观察姿态之一；Jetson 可以使用已有模型和视图入口，但必须与观察姿态编号一致，不能把一张新正视照片当成三张新采集照片。

### 1.2 不纳入本次改造的内容

- 真实多视角人脸重建、视觉里程计和点云融合。
- 为重建新增逐帧 FK、相机位姿遥测或曝光同步协议。
- 将相机安装矩阵、鼻尖三维坐标和绕行中心标定作为演示前置条件。
- 修正整套 FK/DH、启用候选 J1 映射或更改电机逻辑方向。
- 用模型三维坐标驱动机械臂、任意扫描帧回访、新目标身份协议或新医生许可模块。
- 新增扫描阶段连续测距保护；本批保持原机制，不宣称已具备该能力。

这些内容不属于本次交付，不表示问题已经解决。原比赛流程已有的运动学、视觉伺服和安全检查继续有效，不能为完成演示而屏蔽故障。

扫描和后续 `SELECT` 应共用同一版本的正式观察姿态。若换装相机后视野、距离或线缆条件不合适，应先报告并由用户决定调整，不能在扫描模块中另造一套未说明的点位。

## 3. 固定关节轨迹的最小实现

### 3.1 动作顺序

1. 沿用原开始、HOME、公共测距和安全放行流程。
2. 进入基础位置，再到正式左视姿态；真实反馈满足要求后开始扫描。
3. 第一段从正式左视平滑扫描到正式正视，减速停稳；真实到位后报告拍照就绪并保持。
4. Jetson 拍照保存并回传本轮完成。MCU 接受确认后，启动第二段，从正视平滑扫描到正式右视。
5. 右端减速停稳并核对真实反馈，报告扫描完成；正常流程自动衔接返回 HOME，不要求 Qt 再发送一次 HOME 才继续。
6. 采用原 HOME 执行方式及已验证的返回路线，HOME 真实到位后报告完成并允许选视图。

自动回 HOME 只发生在正常扫描完成后。等待照片确认超时、取消或任何运动故障时，停止保持，不继续第二段，也不自动回 HOME。

该动作以五轴关节轨迹实现，不新增相机坐标系下的 FK/IK 弧线求解。相机实际路径是否具有合适的弧形效果、是否持续入镜，以固定模型的整段实测为准。

### 3.2 分段平滑与执行边界

- 使用原工程的平滑运动方法，两段扫描分别平稳起止。第一段到正视速度归零并停稳；第二段仅在保存确认被接受后从静止开始，不要求跨拍照等待保持速度连续。
- 第一段终点和第二段起点采用同一正式正视姿态。等待结束后核对当前反馈，偏离或失效时不能直接从过期状态续扫。
- 正视停顿是明确的业务步骤，不能宣传为左到右不停顿的连续扫描。两段内部仍需平滑，不能用多个不受控跳变的关节命令拼接。
- 返回 HOME 使用原执行方式，并验证从右视开始的整段返回路线，不能因为右视和 HOME 均安全就默认中间运动安全。
- 运动用时依据轨迹长度、保守关节速度/加速度和控制周期确定，参数集中配置；两段扫描、照片等待和 HOME 返回各自配置有限预算，未指定秒数不等于无限等待。
- 沿用原固定内存约束。现有 `view_arc` 的 800 点/8 秒边界不能成为轨迹截断理由；超出时须分段或采用正确的固定内存执行方案，并核查 RAM 占用。
- 取消或故障必须中止尚未执行的节点，旧任务不能在新流程启动后继续发送运动指令。
- 等待照片保存采用非阻塞业务状态，继续处理心跳、中止和反馈，不能用阻塞等待令原安全检查失去执行机会。

### 3.3 J4 角度表示检查

扫描中的 J4 参考角使用连贯的合法表示：`-30 -> 0 -> 35`。当前角、目标角和到位参考角必须处于一致的角域，保留原软限位及电机逻辑方向。

对已发现的受影响入口，应做最小修复或可靠隔离，检查 `0`、`360`、接近 `360`、`345.54` 及等价负角的反馈情形。不得将 `360 -> 3` 解释成约 -357° 的运动，也不得因反馈归一化而把到位参考与反馈比较成相差一整圈。

该检查属于轨迹执行边界，不要求先修改整套 FK，也不作为此前手眼标定旋转矛盾的结论。现有 PC 测试正常不能代替上述边界测试。

## 4. 新采集流程与原定靶流程衔接

```text
原 START / HOME / 公共测距 / 安全放行
  -> 基础位置及左视真实到位，输出关闭
  -> 第一段：左 -> 正 -> 正视真实到位、停稳并保持
  -> MCU 回传正视拍照就绪
  -> Jetson 拍照并保存 -> 回传本轮采集完成
  -> MCU 接受保存确认，启动第二段：正 -> 右
  -> 右视真实到位并停稳 -> MCU 回传扫描完成
  -> MCU 执行返回 HOME，Qt 仍禁止选视图
  -> HOME 真实到位 -> MCU 回传 HOME 完成及允许选择
  -> 原 CAPTURE_CTRL SELECT 1/2/3
  -> 原 SELECTED_VIEW_READY / 新的实时视觉复核与对准
  -> 原 TARGET / P000 / 输出联锁 / 结束返回
```

### 4.1 新增阶段与放行条件

| 阶段 | 允许行为 | 放行或退出条件 |
| --- | --- | --- |
| 扫描准备/第一段执行 | MCU 执行到左视及左到正视的动作；禁止 SELECT 和目标启用 | 正视真实到位且停稳，或中止/故障 |
| 正视等待照片确认 | 机械臂保持，Jetson 拍照保存；禁止第二段、SELECT 和目标启用 | 本轮保存完成确认被 MCU 接受，或等待超时/取消 |
| 第二段执行 | MCU 执行正到右扫描；禁止 SELECT 和目标启用 | 右视真实到位且停稳，或中止/故障 |
| 扫描完成、返回 HOME | 报告扫描完成，正常流程执行 HOME；Qt 仍禁止选择 | HOME 真实到位，或中止/故障 |
| HOME 到位、允许选视图 | 接受原 `SELECT 1/2/3`，进入对应观察姿态 | 选中姿态真实到位后复用原后续状态 |

新阶段名称由代码实现时确定，不能把本表当作现有固件已经具备的状态。

### 4.2 与旧采集门控隔离

现有旧流程通过三点采集记录 `capture_done_mask == 0x07`，并在采集 HOME 后允许 SELECT。新流程应单独记录本轮照片确认、两段扫描完成及 HOME 真实到位，三个条件全部满足且本轮未取消、未故障，才允许 SELECT。

不能直接将旧 `capture_done_mask` 设为 `0x07`：本轮没有完成三次停点拍照。正视保持和右端扫描完成都不是 HOME 完成，不能提前发送 `CAPTURE_HOME_READY`。

原 HOME 执行和真实到位语义可以复用，但新模式的完成处理须识别当前演示阶段及本轮关联，不受旧三点掩码限制，也不能绕过真实 HOME 检查。Qt 必须收到匹配本轮的 HOME 完成及选择放行，不能只因收到扫描完成或保存确认就启用选择入口。

旧逐点模式保留原完成条件。新模式只新增对应的 SELECT 放行分支，选中姿态到位后复用原状态与消息，不另写一套激光执行流程。

### 4.3 后续定靶保持原规则

保存确认和选视图都不是输出许可。选中姿态到位后，Jetson 必须按原流程提供新的实时视觉数据，不能沿用扫描中的旧误差或用预置模型坐标替代实际对准。

P000、视觉有效性、对准、限位、故障及输出硬上限等原条件不变。松开按键、结束输出和返回动作继续服从原比赛流程的实际规则，本次不新增自动输出或故障自动回 HOME。

## 5. 最小通信扩展

最终 TYPE、action、字段宽度和字节布局须由双方共同冻结。本章描述必要语义，不是已实现协议；不能临时借用旧事件值并改变旧消息含义。


| 交互 | 方向 | 必要含义 |
| --- | --- | --- |
| 扫描请求 | Jetson -> MCU | 本轮编号、启动动作；启动固化配方，不传任意关节角或轨迹点 |
| 接受/拒绝 | MCU -> Jetson | ACK 只表示命令接受，不代表到位；状态不允许、忙或反馈异常时拒绝 |
| 正视拍照就绪 | MCU -> Jetson | 关联本轮及启动请求，仅在第一段完成、正视真实到位并停稳后发出 |
| 正视采集完成 | Jetson -> MCU | 关联本轮，表示照片已实际保存；不能以按钮已点击或已收到到位帧代替 |
| 保存确认接受 | MCU -> Jetson | 确认保存应答已接受并衔接第二段；不表示扫描完成、HOME 到位或允许 SELECT |
| 扫描完成 | MCU -> Jetson | 两段扫描均完成、右端真实停稳；随后正常返回 HOME，Qt 仍禁止选择 |
| HOME 完成/允许选视图 | MCU -> Jetson | 本轮照片确认及两段扫描完成，且 HOME 已真实到位；此时才放行原 SELECT |
| 取消/故障 | 双方按原接口处理 | 停止保持、输出关闭、清除新门控，不继续下一段，也不自动回 HOME |

通信要求：

- 现有 payload 上限为 32 字节；本次仅增加编号、动作和状态，不传图像、点云、安装矩阵或逐帧位姿。
- 旧状态消息的长度和字段含义保持兼容，新增关联信息使用双方冻结的新布局，不能直接塞入旧字段。
- SEQ 关联具体请求，本轮编号关联整个演示与拍照确认；同时遵守旧收发端的序号规则。
- 长动作的活动请求必须持续保留关联，不仅依赖旧 3 秒去重窗口；重发不能重复运动。
- 拍照就绪、确认结果、扫描完成和 HOME 完成支持重发或状态查询。Jetson 按本轮编号避免重复拍照；保存确认重发不得再次执行正到右扫描或 HOME。
- MCU 接受确认后可能已进入第二段。若确认 ACK 丢失，重复确认只返回对应结果，不能要求机械臂重新回正视拍照。
- 扫描完成通知不代表 HOME 完成；正常返回不因等待额外的 Qt HOME 指令而卡住。就绪或完成报文丢失时，Qt 查询/重发，不用延时推断到位。
- 迟到、错误编号、取消或复位前的保存确认不能启动第二段或放行 SELECT；旧 HOME 完成消息也不能放行新一轮选择。超时不能被当作完成。
- ACK、两段运动、照片保存和 HOME 返回分别配置有限超时，保留原心跳要求，不把全部超时统一改成运动等待时长。

## 6. MCU、Jetson 与 PC 的任务边界


| 责任方    | 本次任务                                                                                                               | 不承担的任务                                                      |
| ----------- | ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------- |
| MCU/RA6M5 | 固化正式姿态与两段轨迹；真实起终点检查；平滑执行及中止；正视等待保存；右端报告完成并正常回 HOME；HOME 到位后放行；复用原 SELECT、定靶和安全流程 | 不生成三维人脸，不接收模型坐标直接打靶，不发送重建用逐帧位姿 |
| Jetson | 修改原采集入口；发送扫描请求；展示已有模型与扫描过程；正视到位后拍照保存并确认；等待 HOME 到位及放行后允许选择；正确映射观察姿态；选中后提供新视觉数据 | 不通过延时猜测 MCU 到位，不因保存确认或扫描完成提前允许选择，不绕过原视觉复核或输出禁止条件 |
| PC 上位机 | 模拟新请求、状态和确认；支持重发、超时、取消与旧模式回归；保存联调日志                                                 | 不把模拟照片保存、模拟距离或控制 ACK 当成真实采集或安全验收证据   |

Jetson 本次必须提供的数据仅包括：启动请求关联、本轮照片保存完成确认，以及原流程所需的心跳、测距和实时视觉数据。无需提供相机安装矩阵、人脸中心坐标或模型三维控制点。

正视照片保存失败时，Jetson 不回传成功，保留失败信息；MCU 继续按等待期限保持或进入异常处理，不继续向右。照片保存确认只解除第二段的等待条件；只有本轮正常扫描结束、HOME 真实到位并由 MCU 明确放行后，Jetson 才启用观察姿态选择入口。

## 7. 安全边界与异常处理

- 扫描准备、两段执行、正视等待保存、返回 HOME 及待选阶段，P801 始终关闭。P000 不启动扫描，也不绕过原定靶流程开光。
- 保留原测距放行、心跳、限位、CAN/跟踪失败和中止机制，原视觉伺服参数、输出硬上限与指示灯规则不在本次修改范围内。
- 当前安全距离参数按现有固件执行，为 100 mm。原初始测距不能证明后续每个位置均安全，本批也没有新增连续测距保护。
- 固定模型测试前核查两段扫描、右视返回 HOME 及 HOME 到后续观察姿态的整段距离、可达性、视野、支架间隙与线缆；模型或底座位置变化后重新核查。
- 到位以真实关节反馈及原到位检查为依据，不能靠延时、ACK 或轨迹已播完放行；反馈缺失、异常或终点不符时不上报成功。

- 异常处理沿用原停止保持规则，输出关闭，不自动回 HOME；正在正常返回 HOME 时发生异常，同样停止该返回动作。后续恢复须按原明确流程重新操作。
- 本阶段仅面向固定人脸模型、已验证路径、有人值守且物理急停可用的台架，不外推为真人使用安全验证。

### 8.3 固定模型现场验收

1. 先在输出禁止条件下逐点核查正式姿态、距离和视野，再低速验证中间轨迹；不因起终点通过就直接宣称全程通过。

3. 第一段到正视后真实停稳、回传并保持；Jetson 不提前拍照，MCU 未收到匹配保存确认前不继续向右。
4. Jetson 实际拍照保存并确认后，MCU 开始第二段，右端真实停稳后报告扫描完成；此时 Qt 仍不允许选择。
5. 正常返回 HOME 并确认真实到位，MCU 才放行选择；记录照片、本轮关联及双方日志。取消、保存超时或 HOME 返回故障时均不放行。
6. 选择左/正/右之一，确认对应姿态到位并按原规则重新视觉复核。扫描、保存确认和 HOME 到位本身不能触发输出。
