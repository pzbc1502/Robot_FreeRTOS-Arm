# 扫描协调运动与 J4 通信故障复盘

记录日期：2026-10-12。范围：MCU 固定扫描运动、CAN 事务与诊断、PC 模拟握手及现场反馈。原始抓包和运行日志按用户要求仅保留本地，本仓库记录摘要和 SHA256，不上传原始资料或固件产物。

## 1. 本次代码及业务变更

- 公共测距位到左视准备复用固定关节平滑插值，J1/J4/J5 协调移动，避免原逐轴准备时 J4 转动较晚。保持正式左视最终角度及原两段扫描配方，不改 FK/DH；内部新增 MEASURE_TO_LEFT / LEFT_READY，不新增线上动作编号。
- 要求新鲜反馈的控制路径按“收齐五轴角度 -> 发送五轴速度 -> 收齐 F6 确认 -> 下一轮读角度”隔离阶段。仅当前等待轴、正确扩展 ID 和合法 F6 回包可更新确认；拒绝、缺失或发送失败终止普通运动，安全零速度仍尝试全部轴。
- CAN 分包、Emm 速度与参数查询接口返回实际发送结果，避免把发送失败当成成功。五轴共享原新增的 4 ms F6 等待预算，不通过忽略缺反馈或无界重发维持扫描。
- 普通总线错误中断 BEIE 在 BSP 打开模块前启用，不改 FSP 生成文件；中断内保存原始错误位和计数，后台汇总打印。增加 scan_begin 基线和速度确认失败的 tx_ms / wait_ms。
- 协议与项目演示同步已确认的中途免保存合同：FRONT_PHOTO_READY 后回原 PHOTO_DONE=1 作为继续确认，不证明照片已保存；07/82 字节布局和最终正视门控不变。
- 继续保留初始测距、心跳、真实反馈、软件角域、跟踪误差及停止确认。未新增全流程连续深度保护，未处理用户要求暂缓的重复 AUTO 零目标问题，未放开目标执行或激光许可。

## 2. 故障定位过程

1. 初期扫描偶发 J4 角度缺失。can.asc 还显示部分速度确认未到就开始下一轮角度查询，软件确有阶段隔离缺口；该顺序问题已修复，但不等于证明所有丢帧都由它造成。
2. 后续 ram.log 在公共位到左视准备约 0.72 秒报 VEL_ACK missing=08 / rejected=00。缺的是 J4 速度确认，MCU 先故障，PC 再发送 ABORT；27 次发送错误的快照没有扫描起始基线，不能全部归因于该轮。
3. can3 对应的 20:39 测试已使用新增诊断：起始 tx_err/rx_err 均为 0，扫描中新增大量总线错误，含位、填充、格式、ACK 分隔符及警告/被动标志，累计 441 次错误回调。约 10.86 秒后 J4 角度缺失；J4 查询/回包为 1402/1401，五轴速度命令/确认均为 1392/1392，且未出现确认前读角度。
4. 用户更换 J4 驱动板，并确认固件、通信参数、终端电阻和其他配置保持不变。can4 与 21:17 测试核对完整通信及最终正视成功，强烈支持旧 J4 驱动板相关通信故障。尚未拆分板上收发器、供电、内部固件等具体器件原因，也不排除更换时接触状态变化。

终端电阻过多曾是排查假设，不是本轮已证实的唯一根因。相同配置替换驱动板后成功，不证明原终端拓扑已满足规范。CAN 错误是控制器级记录，recent_tx 只表示最近发送上下文，不能据此认定对应关节就是错误源。
