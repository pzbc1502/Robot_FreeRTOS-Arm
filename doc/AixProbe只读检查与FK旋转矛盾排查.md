# AixProbe 只读检查与 FK 旋转矛盾排查

检查日期：2026-10-08。对象：主工程 `Robot_FreeRTOS - Arm`，未操作其他副本。

## 1. 当前结论

**现场已确认：同一正上方观察，J1 正增量顺时针，J4 正增量逆时针；当前 FK 在 HOME 却把两轴正增量都建模为绕基座 +Z。实物与模型的相对正向存在不一致。按基座 +Z 向上的约定，优先怀疑 J1 逻辑角到 DH 角缺少符号映射，而不是 J4 电机正方向或支架长度错误。不能直接改电机方向，也不能据此宣布整套运动学及手眼标定已验收。**

获授权的 J1 小角度复测已完成：用户确认从正上方观察，逻辑角由 90° 增加至 93°时，实物顺时针转动。随后获授权的 J4 相对 +3°与返回测试也已完成，用户后续明确补充去程为逆时针。两次观察不是外部量具测量；已得到方向证据，但角度比例、其他关节轴线与零位仍未独立验收。本次没有因为收到补充观察而再次发送运动指令。

使用 20261007_221641 批次的最终反馈角度进行计算，结果如下。队友 PnP 数值取自此前截图，仅作近似比较，原始旋转矩阵尚未提供给 MCU 侧。

| 姿态变化 | 当前 FK，编译后机器码离线执行 | 计算时仅反转 J1 增量 | 计算时仅反转 J4 增量 | 队友 PnP，约值 |
|---|---:|---:|---:|---:|

## 3. 为什么重点检查 J1/J4

本批 LEFT、FRONT、RIGHT 的 J1 为 84.99°、90°、110.01°；J4 为 345.54°、360°、14.46°。对于朝向计算，J4 可等价理解为 -14.46°、0°、14.46°。

当前 FK 在 HOME 的数学预测是：J1 正向和 J4 正向都绕基座 +Z 方向转动。其余关节的数学正轴如下：

| 关节 | HOME 下当前 DH 模型预测的基座旋转轴 |
|---|---|
| J1 | +Z |
| J2 | +X |
| J3 | -X |
| J4 | +Z |
| J5 | -X |

这张表是模型预测，不是实物测量。正视位下 J4 轴约为 `[0, 0.1683, 0.9857]`，也与 J1 轴接近同向。

因此，当前模型使左右切换时 J1/J4 的主要旋转相叠加；实物同一视角下的正增量方向已由用户确认相反，支持两轴实际存在部分抵消的解释。这与当前 FK 很大、PnP 很小的现象相符。肉眼转向证据还不能替代完整轴线、旋转幅度和相机位姿的测量。

用户补充 J4 方向后，再次在电脑上进行 HOME 与单轴 +3°的离线 FK 核对，J1/J4 的模型正轴均为约 `[0, 0, 1]`，旋转量均为 3°。这次复核没有连接串口或发送任何目标调试命令。

需要区分两个概念：

1. `postive_direction` 规定电机命令的物理转向，并参与编码器反馈的符号转换。
2. DH 的正角方向取决于该关节坐标轴和右手规则。

“命令与反馈相互一致”不保证“逻辑关节角与 DH 角一致”。盲目修改 `postive_direction` 会同时改变命令和反馈的含义，还可能影响回零与限位逻辑，本次不建议这样做。

## 4. 已缩小的范围与仍未排除的问题

### 4.1 不宜再优先尝试的办法

- **改变 J5 后的支架长度来修正旋转量。** DH 中的 a/d 和固定安装平移影响位置，不改变旋转角大小；长度仍须测量，但不能解释 53.7° 与约 6.6° 的差异。
- **把全部工具矩阵统一转置，或换一个固定工具坐标系。** 一致地取逆、变换固定基座或工具坐标系，不改变两姿态之间的旋转角大小。
- **更换 Tsai/Park 等手眼求解算法。** 当前矛盾发生在两侧输入运动的比较阶段，换算法不能把不一致的输入变成正确标定。
- **因为 HOME 看起来正确，就认为整套 FK 正确。** HOME 可能是多项偏置与方向恰好抵消的位置，不能验证其他姿态。

在固定棋盘、固定底座、刚性安装和正确配对的前提下，机器人与相机的相对运动满足 AX=XB。其旋转部分是共轭关系，因此旋转角大小应一致。这里的角度判断来自该关系，不依赖预先知道安装长度。[OpenCV 官方手眼标定说明](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

### 4.2 仍不能排除

- J1/J4 的轴向、零位或逻辑角到 DH 角的映射不正确；其他轴也未独立验证。
- 编码器折算减速比与实际关节输出不一致。
- 照片与反馈不是同一次停稳姿态，或角度未成功刷新。
- 拍摄时底座、棋盘或相机支架发生移动。
- Jetson 的图片尺寸、内参、校正模式、角点顺序或平面 PnP 候选存在问题。低重投影误差不能单独证明位姿正确。

当前没有 Jetson 的完整原始 PnP 旋转矩阵和复核代码，不能宣布 OpenCV 一侧已经排除。J1/J4 相对正向不一致已获得现场方向证据；具体映射、残余差异和完整模型仍须验证，不能宣布只反转 J1 就完成全部修复。

## 5. 用户回来后的最小验证步骤

### 第一步：恢复真正的角度采样

1. 接好电脑文本/日志串口，确认实际 COM 号，关闭占用它的上位机。
2. 机械臂保持停稳，激光关闭，退出自动流程，现场保留可靠支撑和硬件急停。
3. 只执行 `read_all`，保留完整日志。必须看到 `ret=0`、`missing=0x00` 和完整 J1～J5。
4. 在同一静止保持中采样三次，确认没有明显漂移或读取失败。

先不要为了清除 POSE_DEGRADED 就自动回零，也不要启动视觉伺服来刷新矩阵。

### 第二步：先区分 J1/J4 的实物正向

用户不在场时禁止执行。用户返回后，J1/J4 分别获授权测试的反馈与现场方向记录见第 7 节；用户最终确认 J1 正增量顺时针、J4 正增量逆时针。此步骤已有方向观察证据，不需要为了重复已知结论自动追加运动。

在确认真实 HOME、可达范围、线缆余量和现场安全后，每次只测试一个关节的小角度运动。优先验证 J1 和 J4，无需先遍历 J1～J5。测试前后的其他关节应保持不动，读取完整反馈。

用同一个基座观察方向记录两轴逻辑正向的实际转动，比较当前模型预测是否相符。不要分别从电机轴两端观察 CW/CCW 后直接比较，因为视角相反会颠倒结论。

可先用固定机位视频或外壳方向标记做方向筛查；若要确定角度比例、关节零位或完整相机旋转，仍需可靠测量。不能仅凭肉眼给出新的完整 DH 参数。

HOME 下 J5 为 90°，代码上限为 92°，**不能直接安排 J5 +5° 或 +10°**。任何后续 J5 测试必须另行规划。

### 第三步：让 Jetson 提供可复核输入

请队友交付本批每张照片的：

- pose_id、原始图片名和实际尺寸；采用的 K、畸变参数及图像校正模式。
- 完整 `R_target2cam` 或 Rodrigues rvec、tvec、角点排序和 PnP 方法。
- 相对旋转角的计算代码，以及使用的原始矩阵，而不是只有三个最终角度。
- 图片与最新完整 `read_all` 的配对记录。

针对单轴测试，还应按同一次静止保持配对拍照和反馈。每组重复五张有助于检查图像噪声，但不增加独立机器人姿态数。

### 第四步：确认映射后再决定修复范围

若实物验证确认逻辑角与 DH 角存在方向差，应明确建立：

```text
q_DH = s × (q_logic - q_logic_home) + q_DH_home
q_logic = q_logic_home + s × (q_DH - q_DH_home)
s 为 +1 或 -1，必须由验证确定。
```

先在离线数据上复核，不直接把“反转 J4”写入正式固件。真正用于控制时，FK 输入、IK 输出转换、限位判断和连续选解必须一致；不能只改 FK，让 IK 仍输出另一套角度。

结合此次方向观察，按基座 +Z 向上的约定，优先测试的候选为 J1 `s=-1`，逻辑 HOME 与 DH HOME 均为 90°：

```text
J1: q_DH = 90° - (q_logic - 90°) = 180° - q_logic
J1: q_logic = 180° - q_DH
```

这是待验收的运动学转换，不是给驱动器的新角度命令。等价角的范围与连续展开必须统一，不能在不同路径中混用 0°、360°和负角。若用于速度控制，J1 的速度增量也必须在相同的映射边界转换符号；现有电机逻辑速度接口本身不应盲目反向。

建议先让 Jetson 队友用这一候选映射重新生成本批 `T_base_tool`，保持原始 CAN 关节数据不变，与同批原始 `R_target2cam` 比较全部姿态对的旋转量及轴线一致性，再检查手眼方程残差。当前离线结果为 9.5838°、6.3725°、6.3198°，与截图约 9.7°、5.4°、6.6°尚非完全一致。应基于原始数据和约定误差标准判断，不能用截图近似数值直接签收。

映射通过验证后，若用户批准改固件，必须同时处理 FK 输入、IK 输出、IK 分支选择时的当前角参考、逻辑角限位和位置/速度差值。只改相机标定文件或只对 FK 取负，会留下控制路径不一致的风险。J4 的角域修复见第 8 节，是独立问题，不能拿它替代 J1 映射验证。

当前已有电机读写、协议姿态表和回零定义应保持一致，除非新的实物证据证明它们本身错误。单独建立运动学映射通常比盲目改变电机正方向更容易控制影响范围，但仍需验证。

旋转矛盾消除后，再采集含不同旋转轴的额外姿态做手眼标定。HOME 与 FRONT 目前的模型朝向接近一致，现有四组数据的方向激励不足；修正方向并不等于这批数据立即足够标定。OpenCV 要求至少有两次非平行旋转轴的运动，并建议使用更多姿态。[OpenCV 标定采样要求](https://docs.opencv.org/4.x/d9/d0c/group__calib3d.html)

若实际基座 +Z 向上，右手规则下的正向应从正上方看为逆时针，因此该观察支持 J1 逻辑角与 DH 角存在符号映射差异。随后用户最终确认 J4 正增量为逆时针，两轴的实物逻辑正向相反，支持当前 FK 把它们错误叠加的解释；优先离线检验 J1 围绕 HOME 的符号映射。仍需核对基座坐标约定、真实轴线、照片配对及 PnP 输入，不能跳过残余误差验证。

## 8. 另一个已确认的问题：J4 绝对命令跨圈

### 8.1 原因与复现范围

`APP/robot.c` 的 `robot_joint_rotate_to()` 在绝对命令分支中，会把非整圈关节的**目标角**映射到软限位范围，但直接使用 `joint->current_angle` 计算差值，没有先把该**当前角**映射到同一范围。

J4 的软限位为 -90°～90°，但 `read_all` 可能把 -0.0003° 更新为约 359.9997°。随后绝对目标 3° 会得到约 -357° 的差值。

这不是猜测。本次在电脑上执行同一 AXF 中的该函数，在即将调用 `Emm_V5_Pos_Control()` 时截获参数并终止仿真，未执行 CAN 后端，未连接真实运动硬件：

| 虚拟 J4 当前角 | 目标/增量 | 命令方式 | 生成步数 | 折算关节运动量 |
|---:|---:|---|---:|---:|
| 0° | 3° | 绝对目标 | 1,360 | 正向 3° |
| 360° | 3° | 绝对目标 | 161,840 | 反向 357° |
| 360° | +3° | 相对增量 | 1,360 | 正向 3° |

使用当前 J4 减速比 51、每圈 3,200 细分步进行折算。详见 `DEBUG/aixprobe/j4_wrap_command_emulation_20261008.json`。

因此，“以前有时正常”不能排除此问题：它取决于发起绝对命令时的当前角表示。读反馈、等待到位等不同路径可能把当前角分别保存为 0°、360°或等价负角，造成间歇性表现。

### 8.2 对后续测试的影响

- 不能直接用 J4 的绝对小角度命令作为安全的小步保证。
- 下一步若授权 J4 方向验证，应另行确认现场安全，使用固定小角度相对增量，并独立核对返回；本报告不是执行授权。
- 出现异常时先停止，不自动回零、不自动重试。
- 正式修复应在计算绝对运动差值前，把当前角和目标角都映射到该关节的同一合法角域；反馈无效或映射失败时拒绝运动。不能对所有有限行程关节简单套用整圈“最短路径”。
- 对原始 0°、360°、359.9997°、345.54°及相应负角增加回归测试，确认实际生成步数与方向，而不只比较最终朝向矩阵。

**这个问题能解释 J4 绕大圈的安全风险，但不会单独解释 53.7° 与约 6.6° 的朝向差异。** 在 FK 的三角函数中 0°与360°等价；J1/J4 实物正向已有现场记录，但运动学映射及完整模型仍未验收。正式控制代码尚未修改。

### 8.3 相对命令的到位参考也要归一

固定相对增量避免了绝对差值生成 -357°的问题，但不能自动解决到位判断。源码在相对分支中先将增量加到 `joint->current_angle`，再将这个值作为 `robot_joint_wait_target()` 的参考；其比较函数只把反馈角映射到合法角域，没有同样映射参考角。

因此，若当前原始角为 360°、相对增量为 +3°，生成的运动本身只有 +3°，但参考可能是 363°；反馈映射为约 3°，比较误差会接近 360°，造成错误的到位超时。这一结论来自源码路径与差值核对；本次没有在实物上故意触发该超时。

本次在有效反馈自然呈现接近 0°时才执行 +3°，是一次受限验证，不是正式修复，更不能保证以后都正常。后续修复应统一绝对差值计算、相对目标以及到位比较的角域，并补充跨零点的回归测试，不能依赖反复读取碰到 0°表示。
