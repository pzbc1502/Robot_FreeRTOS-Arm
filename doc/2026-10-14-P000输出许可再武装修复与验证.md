# P000 输出许可再武装修复与验证

日期：2026-10-14。

本文记录本日首轮P000修复及当时的构建哈希。本日后续五项异常边界已另外修复，最新交付以[异常边界修复与Jetson对接说明](2026-10-14-控制异常边界修复与Jetson对接说明.md)为准；`Objects`中的同名产物已被后续统一构建覆盖，不能拿本记录的旧哈希核对最新固件。

## 1. 修复范围

本次只修复审查中的第1项：旧按键许可在视觉丢失或失准、随后重新对准时被复用，导致长按P000再次开启输出。

修复前，实际C工作流与定靶状态机的离线复现中，一直按住P000，视觉无效后恢复，对准后模拟输出次数由1变成2。新增回归先在旧代码上失败，错误为`held P000 reused after vision recovery: output_count=2`。

本次不修改扫描路径、FK/DH、视觉增益、初始相机深度100 mm、10秒输出上限、通信字节或PC EXE。不新增医生许可协议。其余5项审查问题尚未修复，不能将本次交付称为全部安全问题解决。

## 2. 现在的行为

| 情境 | MCU处理 |
| --- | --- |
| 新定靶START | 清除旧按键和软件许可，不因已按住P000输出 |
| 视觉无效、过期或丢失对准 | 关闭输出、清旧许可，恢复后可继续对准 |
| 新一轮对准 | 必须观察到稳定松开40 ms，再稳定按下40 ms；始终长按不能重新输出 |
| 输出时松开P000，包括短暂松开 | 按原始按键状态立即关闭并进入HOLD，不等待释放去抖；重新按下不能自动续输出 |
| 输出满10秒 | 关闭并进入HOLD，不因长按自动续期 |
| HOLD后再次输出 | 原规则下显式TARGET START，等待新的有效视觉/稳定对准，再重新按键 |
| 故障、中止或复位 | 清旧许可；原故障保持、停止确认和恢复条件继续生效 |

许可撤销放在`robot_target.c`的状态切换处，保留本次确认阶段到输出阶段的许可，其余阶段切换重新武装。重新按下不能沿用前一次按键的去抖结果。软件许可变量`ROBOT_TARGET_FIRE_ENABLE`在新START及上述撤销点清零，不是新增的医生许可接口。

P000仍不能单独开启输出。原新鲜视觉、稳定帧、工作流、距离锁存、心跳、姿态和运动门控全部保留。上述40 ms为MCU观察到的按键稳定时间，不是独立硬件安全认证。

## 3. 离线验证

`DEBUG/test_scan_target_handoff.py`联合编译实际`robot_workflow.c`和`robot_target.c`，运动、GPIO和串口均为替身。

- 原34个场景保留，本次增加18个场景，共52个场景通过。
- 覆盖无效/过期视觉、输出期间失准、CONFIRM期间失效、持续长按不再输出、重新松开/按下恢复及39/40 ms去抖边界。
- 覆盖故障撤销旧软件许可、10秒上限、HOLD后显式START仍需重新按键、短暂松开立即保持、确认前短暂松开不能沿用旧按下去抖，以及盲区内按键不能预先授权视觉恢复后的输出。
- 停止确认：15个底层场景及30个工作流场景通过。
- 全局软复位：36个工作流、14个UART及3个联合场景通过。
- 中止后重新开始：11个场景通过。
- 视觉伺服、定靶指示及关闭保持静态检查通过。

旧`test_workflow_state_machine_static.py`仍硬编码初始150 mm，运行在该断言处失败；当前双方已冻结100 mm。本次未修改该阈值或历史脚本，不宣称所有历史测试通过。全仓库格式检查还会遇到用户日志首行已有尾部空格，本次不改原日志，仅检查本次源代码、测试及文档。
