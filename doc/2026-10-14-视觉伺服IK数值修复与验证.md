## 1. 日志事实与根因边界

依据 `UpperComputer/dist/logs/ra6m5_upper_console_20261014_114358.log`：

- 11:46:16.611，扫描、扫后 HOME、最终正视完成，进入 SCAN_READY。
- 11:46:51.467，显式定靶交接成功，进入 TARGET_ACTIVE；没有卡在原定靶门控。
- 11:46:58.869～58.912，视觉伺服连续三次 inverse failed，锁存内部 fault=3，即 IK 类别，不是 J3 编号。
- MCU 随后进入 FAULT_HOLD，Jetson 才发 ABORT_HOLD，11:46:59.227 有新五轴反馈停止确认。

当前 C 逆解存在已复现的数值缺陷：J1 半角公式用 `fabs(py-eq2)>1e-4` 选择符号。近似日志起点及同方向平移的离线回放，在 X+3.78/Z-3.78 mm 时，仅 0.000106812 mm 的浮点残差就使正常约91.23度变成268.77度，导致全部候选失效。

这证明软件缺陷存在，并符合本轮 IK 失败表现；旧日志没有完整失败矩阵和关节候选，不能宣称已精确重放现场唯一根因，也不能将离线位移当作实测停止距离。

## 2. 已实现修改

### 2.1 稳定 J1 逆解

`Middle/robot_kinematics.c` 改为按有符号径向长度选分支的 atan2，不再以极小 Y 残差翻转角度。保留非有限值、轴线退化和径向几何一致性拒绝；径向容差仅用于浮点解算，形式为 `0.001 mm + 16*FLT_EPSILON*尺度`。

共享 `ROBOT_ERROR_RANGE=1e-4`、其他关节求解、角域限制、最优解权重及分支惩罚均未改。不增加强行可达分支。该函数由 AUTO、时间轨迹、遥控和视觉路径共享，不把修改描述为只影响视觉。

### 2.2 视觉运动门控

`APP/robot.c` 复用已有有限速/跟踪门控的 PID 路径，不再让视觉控制沿用通用200度/秒上限及零跟踪门槛。

| 检查 | 本版软件限制 |
| --- | --- |
| J1～J5 指令角速度 | 每轴不超过8度/秒 |
| 新反馈到目标的跟踪误差 | 8度；不合格周期请求零速，不继续发送普通运动速度 |
| 相邻成功目标关节变化 | 名义20 ms周期下不超过0.161度，含0.001度数值余量 |
| 首次目标相对同步反馈 | 额外允许原FK/IK同步误差3度，即最多3.161度；首周期前馈仍为0，仍受8度/秒限速 |
| 候选关节角 | 有限并可映射到原合法角域，处理全周跨零及J4的330/-30等价角 |
| 五轴 FK 回验 | XYZ各分量误差不超过0.01 mm，工具Z轴各分量误差不超过0.001 |

J6仍为非运动夹爪，求解后固定为0；回验位置和工具Z轴，不要求自由滚转。工具Z轴不自动等于相机光轴，也不构成手眼标定。FK回验是当前数学模型自洽性检查，不证明真实毫米精度、支架包络或整个空间无碰撞。

目标跳变、非法角度或FK残差失败，在提交该目标的PID速度之前拒绝并锁存故障；不得以新视觉自动恢复。反馈/跟踪不合格沿用有限次数停止路径。三次连续IK失败上限、心跳、视觉新鲜度、CAN确认和显式ABORT停止确认仍保留。8度/秒和8度是采用已有扫描相同数值的保守软件边界，不是本次视觉速度或制动性能的实机验收值。

### 2.3 有界失败诊断

- `[VS_GUARD]`：目标非法、关节步进、FK残差等拒绝原因。
- `[VS_IK]`：零速请求提交后打印失败矩阵及候选；连续IK失败仅首个周期打印完整信息，不正常周期刷屏。
- `[IK] geometry_invalid/invalid`：区分几何阶段失效和最终失效掩码；各bit是候选索引，不是关节编号。
- `[IK_REJECT]`：几何阶段通过但角域/有限性检查失败的候选与关节边界。
- 矩阵/候选用9位有效数字输出，保留float32重放精度。零速发送失败时跳过长诊断，保持反馈故障并继续停止处理。

日志的 stop requested 仅表示请求停止，不证明停稳。真实停止仍以原同SEQ的81/20 06 00为协议确认，并需现场独立验证实际停止性能。
