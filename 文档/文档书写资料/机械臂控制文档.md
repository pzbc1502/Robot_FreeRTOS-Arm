## 1. 工程范围

当前主要启动路径包括机械臂控制任务、P015 激光初始化和视觉定靶线程：

```text
robot_thread_entry
    -> LED_Init
    -> BSP_Laser_Init
    -> BSP_UART_Init
    -> BSP_CAN_Init
    -> robot_init
        -> robot_control_task
        -> robot_cmd_service
vision_service_thread_entry
    -> jetson_vision_init
    -> robot_target_init
    -> 10 ms 周期运行 jetson_vision_process + robot_target_step
```

机械臂运动学控制 J1~J5，J6 由夹爪模块独立控制。`vision_service_thread` 当前负责 Jetson 视觉误差解析和激光定靶状态机，不再驱动旧视觉采摘流程。

工程中已移除旧 `K230_cmd` 和 `robot-take` 编译项，改为 `jetson_vision` 和 `robot_target`。底盘、DHT11、MQTT、W800 等外围模块仍保留，因此 4.1 工程裁剪仍是部分完成。

## 2. 当前控制架构

### 2.1 事件与任务

UART/MQTT 命令进入 `g_robot.cmd_queue`，由 `robot_cmd_service` 解析后发送控制事件；`robot_control_task` 串行处理机械臂事件。

主要事件包括：

- 单关节相对/绝对旋转
- 自动笛卡尔运动
- 时间函数轨迹
- soft reset / hard reset
- remote 连续控制
- J1~J5 批量角度读取

AUTO 在当前位姿无效时会被拒绝。反馈读取异常但仍可继续时，系统使用 `ROBOT_STATUS_POSE_DEGRADED` 标记退化状态。

### 2.2 AUTO 运动流程

```text
目标位移
    -> 10 ms 正弦速度 S 曲线笛卡尔插值
    -> 每个路径点进行逆运动学求解
    -> IK 分支锁定选择连续解
    -> 每 10 ms 更新一个关节目标节点
    -> 每个路径点执行一次前馈 + P 控制
    -> 终点保持 10 个控制周期，前馈清零并由 P 项收敛
    -> J1~J5 非阻塞发送速度命令
    -> 结束后批量停止 J1~J5
```

路径和逆解结果使用静态缓冲区：

```c
#define ROBOT_MAX_PATH_SIZE (600)

static struct position s_path_buf[ROBOT_MAX_PATH_SIZE];
static float s_result_buf[ROBOT_MAX_PATH_SIZE * ROBOT_MAX_JOINT_NUM];
```

路径最多保存 600 点；S 曲线达到容量上限时会把最后一点强制替换为目标点。AUTO 和时间函数运动不再在运行时分配路径/逆解内存。

### 2.3 前馈 + P 控制器

控制周期为 10 ms（100 Hz），控制器结构为：

```c
error = shortest_angle_diff(current_angle, target_angle);
velocity = feedforward + ROBOT_JOINT_KP[joint] * error;
velocity = clamp(velocity, -200.0f, 200.0f);
```

各关节 Kp（单位 `1/s`）：

```c
{0.65f, 4.00f, 2.50f, 1.00f, 1.00f, 10.0f}
```

控制器无积分项和微分项，不存在原 PID 的积分饱和问题。

前馈时间基准按目标更新周期计算：

- AUTO：S 曲线每 10 ms 生成一个目标点，相邻 IK 节点角差除以 10 ms，并使用全量前馈。
- 时间函数：同样按 10 ms 生成目标点，但路径由时间函数直接给出，不经过 S 曲线规划器。
- remote：相邻目标角差除以 50 ms；首次更新前馈为 0，避免进入模式时产生冲击。
- 角差通过 `robot_angle_diff()` 归一化到 `[-180, 180]`，避免跨越 0/360 度时方向错误。

`ave_error` 使用实际控制采样次数作为分母，表示各关节的平均绝对跟踪误差，不再按路径点数错误放大。

### 2.4 CAN 反馈与控制输出

每个控制周期采用并行反馈读取：

1. 清除 `motor_rx_flag` 和残留 RX 信号量。
2. 连续发送 J1~J5 位置读取请求。
3. CAN ISR 按电机地址将 `0x36` 回包写入独立缓存并置位。
4. `BSP_CAN_WaitAllMotors()` 统一等待，当前批量等待上限为 6 ms。
5. 解析已收到的回包并更新关节角度。

速度控制使用 `robot_joint_velocity_nowait()`：发送 `0xF6` 后立即返回，不逐关节等待应答。CAN 总线仍由互斥锁保护，避免与夹爪、单关节读取等操作互相干扰。

停止操作使用 `robot_joint_stop_all()`：连续发送所有 stop 命令，再通过 `motor_stop_flag` 统一等待 `0xFE` 回包。

`BSP_CAN_DrainRx()` 当前负责清空 RX 信号量，避免残留广播帧或旧通知消耗下一次请求的应答窗口。

### 2.5 复位与位姿有效性

soft reset 当前流程：

1. 读取并映射各关节当前角度。
2. 发送位置模式回 HOME 命令。
3. 根据初始角度误差估算行进时间，并增加 300 ms 余量。
4. 每 40 ms 轮询反馈，最少等待 320 ms，最多等待 3 s。
5. 校验 HOME；失败时执行最多 3 个 refine pass。
6. 每个关节每个 pass 最多微调 3 轮，容差为 1.0 度。
7. 最终校验通过后设置 HOME 位姿；失败则清除 `POSE_VALID` 并进入退化状态。

`robot_angle_map()` 对距离 min/max 不超过 0.1 度的读数直接夹紧到边界，避免边界噪声被错误卷绕到另一圈。soft reset 映射还提供额外 1 度边界容差。

当前 J2/J3/J5 的软件限位相对 HOME 留有 2 度余量：J2 下限 88 度、J3 下限 -92 度、J5 上限 92 度。

### 2.6 IK 连续性

逆运动学已经实现分支锁定：

- 使用加权平方角度距离选择最接近当前姿态的有效解。
- 权重为 `{20, 15, 12, 5, 3, 1}`。
- 对非上一帧分支乘以 `IK_SWITCH_PENALTY = 10`，降低路径中途跳解概率。
- 新 AUTO、时间函数、remote 和复位完成后调用 `robot_kinematics_reset_branch_lock()`，首帧重新从实际姿态选择最近解。
- J6 不参与整臂轨迹驱动，AUTO/时间函数保持进入运动时的 J6 角度。

当前只处理了精确奇异点的基础分支，尚未实现 4.7 的奇异区连续阻尼。

### 4.7 奇异点三次阻尼

目标是在腕部接近奇异区时连续降低 J4 分量，而不是只在精确奇异点切换公式。建议继续参考 `MechanicalArm_Code_V4-main`：

- 根据 `sin(theta5)` 或等价奇异度构造连续权重。
- 奇异区外权重为 1，进入奇异区后平滑衰减到 0。
- 使用三次平滑函数保证权重及其一阶导数连续。
- 锁定或缓慢更新 J4，并由其余腕部自由度补偿。
- 上板验证 J4/J5 在奇异区附近不存在突跳。

### 4.8 S 曲线轨迹规划

AUTO 已切换到 `robot_path_interpolation_scurve()`，路径直接写入 `s_path_buf`。当前实现参考 `MechanicalArm_Code_V4-main`，按 10 ms 时间步长积分正弦速度剖面：

- `Vmax = 300 mm/s`，`Amax = 500 mm/s²`。
- `Omega = 2*Amax/Vmax`，加速段时长约 0.9425 s，加速段位移约 141.76 mm。
- 路径不短于约 283.53 mm 时使用“加速 + 匀速 + 减速”三段式。
- 短路径使用“加速 + 减速”两段式，并根据距离降低峰值速度。
- 每步按 `s += v(t)*0.01` 生成变距笛卡尔目标，并将最后一个点强制设为精确目标。
- 最大生成 600 点；达到容量上限时最后一点仍会被替换为目标点。
- `robot_pid_run()` 每个目标点只执行一次 10 ms 控制周期，前馈使用相邻关节目标角差除以 10 ms。
- 轨迹结束后追加 10 个控制周期的终点稳定段：前馈清零，只保留 P 项收敛，然后批量停止电机。
- MQTT 关节同步改为每 10 个路径点执行一次，约 100 ms 一次。

代码实现已完成，仍需重点验证：

1. `auto 0 -70 0` 的启停平滑性和各关节 `ave_error`。
2. `auto 0 -140 0` 等长路径不触发 600 点截断。
3. `auto 0 0 100` 不产生 IK 失败或前馈限幅持续饱和。
4. 近零位移当前只生成 1 个路径点，而 `robot_pid_run()` 从索引 1 开始处理；进入末端稳定段前目标数组可能仍为零值，该边界必须修复并回归验证。
5. 如果路径达到 600 点上限，最后一点被强制替换为目标，需确认不会形成末端大步跳变。

#### Jetson -> RA6M5 协议

当前只识别一种视觉误差帧：

```text
[0xFF][0x05][0x03][dcx_lo][dcx_hi][dcy_lo][dcy_hi][checksum][0xFE]
```

| 字段     |       值 | 说明                                           |
| -------- | -------: | ---------------------------------------------- |
| SOF      | `0xFF` | 帧起始                                         |
| LEN      | `0x05` | `FUNC(1) + DATA(4)`                          |
| FUNC     | `0x03` | `JETSON_FUNC_VISION_ERROR`，视觉误差帧       |
| DATA     |   4 字节 | `int16_t dcx` + `int16_t dcy`，小端        |
| CHECKSUM |   1 字节 | `LEN + FUNC + DATA...` 的 `uint8_t` 截断和 |
| EOF      | `0xFE` | 帧结束                                         |

解析状态机只接受 `SOF=0xFF`、`LEN=0x05`、`FUNC=0x03`、4 字节 payload、匹配 checksum 和 `EOF=0xFE`。旧 K230 的 `0x02` 草莓检测、`0x04` 可采摘判断、`0x06` 数量帧已经删除，不再被解析。

`dcx/dcy` 含义：

- `dcx`：画面 X 轴像素偏差，正方向由 Jetson 端定义，当前控制侧按 `TARGET_KX_MM_PER_PX=-0.38f` 映射到机械臂 X 修正。
- `dcy`：画面 Y 轴像素偏差，当前控制侧按 `TARGET_KY_MM_PER_PX=0.35f` 映射到机械臂 Z 修正。

#### Jetson -> RA6M5 定靶状态机启停控制帧（当前实现）

当前在同一个 Jetson UART 接收通道中兼容 4 字节启停控制帧，不新建第二套通信模块：

```text
[0xAA][FUNC][VALUE][0xBB]
```

| 字段  | 值              | 说明                         |
| ----- | --------------- | ---------------------------- |
| SOF   | `0xAA`        | 启停控制帧头                 |
| FUNC  | `0x01`        | 定靶状态机控制               |
| VALUE | `0x01`/`0x00` | `0x01` 启动，`0x00` 关闭 |
| EOF   | `0xBB`        | 启停控制帧尾                 |

示例：

```text
AA 01 01 BB   // Jetson 请求启动 target 状态机
AA 01 00 BB   // Jetson 请求关闭 target 状态机
```

解析策略：

- `0xFF ... 0xFE` 仍按现有视觉误差帧解析，保持 `FF 05 03 ... checksum FE` 不变。
- `0xAA 0x01 value 0xBB` 作为状态机启停帧，仅接受 `value=0x01/0x00`。
- 非 `0xFF` / `0xAA` 字节直接忽略；控制帧 `FUNC`、`VALUE` 或 `EOF` 非法时丢弃当前帧，不改变状态机。
- 启停控制帧不携带 checksum，原因是只有 4 字节、只控制布尔开关，最小实现优先；需要抗干扰增强时再增加校验。




#### RA6M5 -> Jetson 回传

状态回传格式保持 4 字节：

```text
[0xCC][FUNC][VALUE][0xDD]
```

当前回传定义如下：

|     FUNC | 宏                           |    VALUE | 当前含义                              |
| -------: | ---------------------------- | -------: | ------------------------------------- |
| `0x01` | `RA6_TO_JETSON_READY`      | `0x01` | 机械臂已到预定位，Jetson 可发送视觉帧 |
| `0x02` | `RA6_TO_JETSON_ALIGN_DONE` | `0x01` | 连续稳定对准完成，等待输出许可        |
| `0x03` | `RA6_TO_JETSON_OUTPUT`     | `0x01` | 激光输出已进入激活状态                |
| `0x03` | `RA6_TO_JETSON_OUTPUT`     | `0x00` | 激光输出已切断                        |
| `0x04` | `RA6_TO_JETSON_TARGET_CTRL` | `0x01` | 定靶状态机已启用                      |
| `0x04` | `RA6_TO_JETSON_TARGET_CTRL` | `0x00` | 定靶状态机已关闭或启用失败            |
| `0xFE` | `RA6_TO_JETSON_ERROR`      | `0x01` | 当前实现用于限位/急停类错误上报       |

`jetson_send_status_u8()` 使用 `R_SCI_UART_Write()` 异步发送，并通过 `jetson_notify_tx_complete_from_isr()` 释放发送完成信号量，等待超时为 20 ms。

启停状态机回传示例：

```text
CC 04 01 DD   // RA6M5 回传：状态机已启用
CC 04 00 DD   // RA6M5 回传：状态机已关闭，或启动请求被拒绝后保持关闭
```

#### 对外 API

```c
void jetson_vision_init(void);
void jetson_vision_process(void);
bool jetson_get_vision_error(int16_t *dcx, int16_t *dcy);
bool jetson_get_target_control(bool *enable);
bool jetson_send_status_u8(uint8_t func, uint8_t value);
void jetson_notify_tx_complete_from_isr(void);
```

该接口和 `jetson_get_vision_error()` 一样只消费一次新命令；视觉线程在 `jetson_vision_process()` 后先消费启停命令，再组装 `target_obs_t` 运行 `robot_target_step()`。

运行方式：

1. `vision_service_thread_entry()` 启动时调用一次 `jetson_vision_init()`。
2. `jetson_vision_init()` 创建 TX 信号量、复位 parser、打开 `robot_jeston_ctrl/robot_jeston_cfg`，启动 1024 字节 RX 缓冲读取。
3. 视觉线程每 10 ms 调用 `jetson_vision_process()`。
4. `jetson_vision_process()` 通过 transfer `infoGet()` 的 `transfer_length_remaining` 计算当前写入位置，增量解析新字节；当 `remaining==0` 时解析尾段并重新启动 `R_SCI_UART_Read()`。
5. 合法视觉帧解析完成后更新 `s_latest_dcx/s_latest_dcy`，置位 `s_new_error`。
6. 合法启停控制帧解析完成后更新 `s_target_control_enable`，置位 `s_new_target_control`。
7. `jetson_get_target_control()` 只消费一次启停命令；`jetson_get_vision_error()` 只在有新帧时返回 `true`，并清除 `s_new_error`，因此上层的“连续 3 帧”判定不会重复消费同一帧。

#### 通信异常处理

当前视觉通信采用“严格接收、失败丢弃、只消费合法新帧”的策略；启停控制帧沿用同一原则：

| 异常场景                     | 当前处理                                              | 安全意义                                     |
| ---------------------------- | ----------------------------------------------------- | -------------------------------------------- |
| 收到非`0xFF/0xAA` 字节     | parser 保持`JETSON_PARSER_WAIT_SOF`，直接忽略       | 串口噪声不会进入业务数据                     |
| `LEN != 0x05`              | `parser_reset()`，丢弃当前帧                        | 防止旧协议或错误长度污染解析                 |
| `FUNC != 0x03`             | `parser_reset()`，丢弃当前帧                        | 旧 K230 的 0x02/0x04/0x06 不会被当作视觉误差 |
| checksum 不匹配              | `parser_reset()`，丢弃当前帧                        | 防止错误`dcx/dcy` 驱动机械臂移动           |
| `EOF != 0xFE`              | 不更新视觉误差并复位 parser                           | 半帧、错帧不会生成新目标                     |
| `AA` 控制帧非法             | 丢弃当前控制帧，不改变 `ROBOT_TARGET_ENABLED`          | 错帧不会误启动或误关闭状态机                 |
| Jetson 启动被拒绝           | 保持状态机关闭，拉低 P015，并回传 `CC 04 00 DD`       | pose invalid 时不会进入正式定靶              |
| transfer`infoGet()` 失败   | 本周期直接`return`                                  | 不使用未知 DMA/DTC 状态                      |
| RX 缓冲写满                  | 先解析尾段，再重新启动`R_SCI_UART_Read()`           | 避免环形接收停住                             |
| UART 打开失败                | 打印错误并`__BKPT(0)`                               | 初始化阶段阻断错误硬件配置                   |
| RX 启动失败                  | 打印错误，不置位新视觉帧                              | 不制造虚假视觉输入                           |
| TX 发送失败或 20 ms 内未完成 | `jetson_send_status_u8()` 返回 `false` 并打印错误 | 状态回传失败不会阻塞控制任务                 |

注意：通信层只负责保证“坏帧不进入状态机”。视觉超时后的安全动作由 4.11 的 `TARGET_ALIGN/TARGET_CONFIRM/TARGET_OUTPUT` 处理。

### 4.11 激光定靶状态机（当前实现）

#### 当前代码位置

| 文件                                  | 当前职责                                                                                              |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| `APP/robot_target.c`                | 定靶状态机、视觉误差闭环、小步 AUTO 修正、P015 激光输出安全控制                                       |
| `APP/robot_target.h`                | 定靶参数、`target_obs_t`、启用开关和 API                                                            |
| `src/vision_service_thread_entry.c` | 周期组装`target_obs_t` 并驱动 `robot_target_step()`                                               |
| `USER_BSP/bsp_laser.c/.h`           | P015 激光 GPIO 底层，高电平开、低电平关；P000 KEY 发射许可输入                                        |
| `Middle/robot_cmd.c`                | 提供`target_enable` / `target_disable` 状态机开关；保留 `laser_on` / `laser_off` 串口调试命令 |

#### 启用开关

```c
volatile bool ROBOT_TARGET_ENABLED = false;
volatile bool ROBOT_TARGET_FIRE_ENABLE = false;
```

- `ROBOT_TARGET_ENABLED=false` 时，`robot_target_step()` 停留在 `TARGET_INIT`，不进入定靶流程；串口 `target_disable` 会立即执行一次 `BSP_Laser_Off()`。
- 串口 `target_enable` 只有在 `ROBOT_STATUS_POSE_VALID` 已置位后才会成功；未先 `soft_reset` 建立有效位姿时会拒绝启用并保持激光关闭。
- 串口 `target_enable` 成功后将 `ROBOT_TARGET_ENABLED` 置为 true，状态机重新接管 P015 激光输出。
- 串口 `target_disable` 将 `ROBOT_TARGET_ENABLED` 置为 false，清除 `ROBOT_TARGET_FIRE_ENABLE` 调试覆盖并立即关闭 P015；随后状态机释放 P015，便于使用 `laser_on` / `laser_off` 做硬件调试。
- Jetson 二进制控制帧 `AA 01 01 BB` / `AA 01 00 BB` 与串口 `target_enable` / `target_disable` 走同一安全入口，不复制第二套启停逻辑。
- Jetson 启动请求同样必须满足 `ROBOT_STATUS_POSE_VALID`；成功回传 `CC 04 01 DD`，失败保持关闭并回传 `CC 04 00 DD`。
- Jetson 关闭请求始终允许执行：清除 `ROBOT_TARGET_ENABLED`、`ROBOT_TARGET_FIRE_ENABLE` 并立即关闭 P015，回传 `CC 04 00 DD`；它不是机械臂急停，也不取消已经进入队列或正在执行的 AUTO。
- P000 板载 KEY 已接入 `target_obs_t.fire_button`，按下为低电平；未按住 KEY 时，即使视觉对准完成，也不会进入正式激光输出。
- `ROBOT_TARGET_FIRE_ENABLE=false` 仍保留为调试/测试覆盖的默认安全状态，不作为比赛正式发射输入。

#### 周期任务运行

`vision_service_thread_entry.c` 当前运行流程：

```c
jetson_vision_init();
robot_target_init();

while (1) {
    target_obs_t obs = {0};
    obs.now_ms = HAL_GetTick();

    jetson_vision_process();
    bool target_enable = false;
    if (jetson_get_target_control(&target_enable)) {
        bool enabled = false;
        if (target_enable) {
            enabled = robot_target_enable_request();
        } else {
            robot_target_disable_request();
        }
        jetson_send_status_u8(RA6_TO_JETSON_TARGET_CTRL, enabled ? 1u : 0u);
    }
    obs.has_vision = jetson_get_vision_error(&obs.dcx, &obs.dcy);
    obs.fire_button = BSP_Laser_FireKey_IsPressed();

    robot_target_step(&obs);
    vTaskDelay(pdMS_TO_TICKS(10));
}
```

也就是说，视觉解析和状态机都是 10 ms 调度；真正的对准运动限频在 `TARGET_ALIGN_PERIOD_MS=200` 内部完成。

#### 状态机运行

当前状态枚举：

```text
TARGET_INIT
  -> TARGET_PRE_POSITION
  -> TARGET_WAIT_DETECT
  -> TARGET_ALIGN
  -> TARGET_CONFIRM
  -> TARGET_OUTPUT
  -> TARGET_DONE / TARGET_RECOVER
```

| 状态                    | 当前实现                                                                                                                                                                                                                        |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `TARGET_INIT`         | 关激光，目标设为预定位`TARGET_PRE_X/Y/Z`，清零稳定计数，调用 `robot_send_auto_event()` 移动到预定位；发送成功后进入 `TARGET_PRE_POSITION`                                                                                 |
| `TARGET_PRE_POSITION` | 持续关激光；当`g_robot.cur_pos` 距目标 X/Y/Z 均不超过 1 mm，回传 `RA6_TO_JETSON_READY=1`，进入 `TARGET_WAIT_DETECT`                                                                                                       |
| `TARGET_WAIT_DETECT`  | 持续关激光；等待`vision_fresh()` 成立，即收到 500 ms 内的新视觉误差帧，进入 `TARGET_ALIGN`                                                                                                                                  |
| `TARGET_ALIGN`        | 持续关激光；视觉超时则清零稳定计数并进入`TARGET_RECOVER`；误差在阈值内时只在新帧到达时累计稳定帧数；连续 3 帧达标后回传 `RA6_TO_JETSON_ALIGN_DONE=1`，进入 `TARGET_CONFIRM`；未达标时每 200 ms 发送一次小步 `AUTO` 修正 |
| `TARGET_CONFIRM`      | 持续关激光；视觉超时进入`TARGET_RECOVER`；只有 `fire_allowed=true` 时回传 `RA6_TO_JETSON_OUTPUT=1` 并进入 `TARGET_OUTPUT`                                                                                               |
| `TARGET_OUTPUT`       | `fire_allowed` 仍为 true 且视觉未超时时调用 `BSP_Laser_On()`；许可撤销或视觉超时则先 `BSP_Laser_Off()`，回传 `RA6_TO_JETSON_OUTPUT=0`，进入 `TARGET_DONE`                                                             |
| `TARGET_DONE`         | 关激光；等待`fire_allowed=false` 后清零稳定计数并回到 `TARGET_WAIT_DETECT`                                                                                                                                                  |
| `TARGET_RECOVER`      | 关激光；等待 200 ms 后清零稳定计数并回到`TARGET_WAIT_DETECT`                                                                                                                                                                  |

全局安全入口：每次 `robot_target_step()` 开头都会检查 `obs->estop_active`、`obs->limit_triggered` 和所有关节的 `ROBOT_STATUS_LIMIT_HAPPENED`。任一触发时立即关激光，回传 `RA6_TO_JETSON_ERROR=1`，进入 `TARGET_RECOVER`。

#### 视觉精瞄实现

当前参数定义在 `robot_target.h`：

| 参数                          |     当前值 | 说明                            |
| ----------------------------- | ---------: | ------------------------------- |
| `TARGET_PRE_X`              |   `0.0f` | 预定位 X                        |
| `TARGET_PRE_Y`              | `-50.0f` | 预定位 Y                        |
| `TARGET_PRE_Z`              |   `0.0f` | 预定位 Z                        |
| `TARGET_KX_MM_PER_PX`       | `-0.38f` | 像素 X 误差到机械臂 X 修正      |
| `TARGET_KY_MM_PER_PX`       |  `0.35f` | 像素 Y 误差到机械臂 Z 修正      |
| `TARGET_MAX_STEP_MM`        |   `1.5f` | 单次 X/Z 修正限幅               |
| `TARGET_ALIGN_TOL_PX`       |  `30.0f` | 对准阈值                        |
| `TARGET_ALIGN_STABLE_COUNT` |      `3` | 连续 3 个新视觉帧达标才确认对准 |
| `TARGET_ALIGN_PERIOD_MS`    |    `200` | 两次 AUTO 小步修正的最小间隔    |
| `TARGET_VISION_VALID_MS`    |    `500` | 视觉帧有效期                    |

`TARGET_ALIGN` 的实际修正方式：

```c
float dx = clamp(dcx * TARGET_KX_MM_PER_PX, -TARGET_MAX_STEP_MM, TARGET_MAX_STEP_MM);
float dz = clamp(dcy * TARGET_KY_MM_PER_PX, -TARGET_MAX_STEP_MM, TARGET_MAX_STEP_MM);

target = g_robot.cur_pos;
target.x += dx;
target.z += dz;
robot_send_auto_event(&target);
```

注意这里不是无限累加旧目标，而是以当前 `g_robot.cur_pos` 为基准做小步修正，降低旧目标残留导致的过冲风险。

#### 激光输出安全链路

正式链路只在 `TARGET_OUTPUT` 中调用 `BSP_Laser_On()`，其它状态持续调用或确保 `BSP_Laser_Off()`。退出、超时、限位、急停、未许可时都会先关激光。

`laser_on` / `laser_off` 串口命令仍保留在 `robot_cmd.c`，仅用于 P015 调试。调试时应先发送 `target_disable`，否则状态机在启用后会按安全链路重新接管 P015。它们不会改变 `ROBOT_TARGET_ENABLED`、`ROBOT_TARGET_FIRE_ENABLE`、P000 KEY 读取结果或状态机状态，因此不属于正式定靶安全输出路径。

#### 异常处理与安全保障

当前定靶链路采用“默认关闭、显式启用、持续校验、异常先关断”的策略：

| 保障点               | 当前代码行为                                                                                                             | 作用                                            |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| 上电默认低电平       | `BSP_Laser_Init()` 将 P015 配置为输出低电平，并立即调用 `BSP_Laser_Off()`；同时将 P000 配置为输入上拉                | 上电后激光默认关闭，KEY 未按下时许可为 false    |
| 状态机默认禁用       | `ROBOT_TARGET_ENABLED=false`                                                                                           | 未显式启用时不会进入定靶动作                    |
| 串口启用状态机       | `target_enable` 先检查 `ROBOT_STATUS_POSE_VALID`，通过后将 `ROBOT_TARGET_ENABLED=true` 并调用 `BSP_Laser_Off()`  | 未复位时拒绝进入正式定靶                        |
| 串口关闭状态机       | `target_disable` 将 `ROBOT_TARGET_ENABLED=false`、`ROBOT_TARGET_FIRE_ENABLE=false`，并立即调用 `BSP_Laser_Off()` | 退出正式定靶、清除调试覆盖并关闭 P015           |
| Jetson 启停帧        | `AA 01 01 BB` / `AA 01 00 BB` 复用串口启停的同一安全入口，并用 `CC 04 01/00 DD` 回传结果                      | Jetson 可启动/关闭定靶，但不能绕过 pose 校验     |
| 发射许可默认禁止     | `BSP_Laser_FireKey_IsPressed()` 读取 P000，默认未按下为 false                                                          | 对准完成也不会自动开激光                        |
| 软件调试覆盖默认关闭 | `ROBOT_TARGET_FIRE_ENABLE=false`                                                                                       | 保留测试入口，但比赛正式输入使用 P000 KEY       |
| 禁用时释放调试       | `robot_target_step()` 检测到 `!ROBOT_TARGET_ENABLED` 后只回到 `TARGET_INIT`，不周期性抢占 P015                     | `target_disable` 后可用 `laser_on/off` 调试 |
| 非输出状态关断       | `TARGET_INIT/PRE_POSITION/WAIT_DETECT/ALIGN/CONFIRM/DONE/RECOVER` 均会关激光                                           | 激光只可能在`TARGET_OUTPUT` 内打开            |
| 限位/急停入口        | 每周期检查`obs->estop_active`、`obs->limit_triggered` 和所有关节 `ROBOT_STATUS_LIMIT_HAPPENED`                     | 任一触发立即关激光并进入恢复                    |
| 错误上报             | 限位/急停类异常回传`RA6_TO_JETSON_ERROR=1`                                                                             | Jetson 可停止发送或提示异常                     |
| 视觉超时保护         | `TARGET_ALIGN`、`TARGET_CONFIRM`、`TARGET_OUTPUT` 都检查 `vision_fresh(now)`，500 ms 无新帧即退出当前动作        | Jetson 掉线或视觉卡死时不会继续输出             |
| 小步修正限幅         | X/Z 单步修正限制在`±1.5 mm`，且两次修正间隔至少 200 ms                                                                | 降低视觉误差突变造成的大动作风险                |
| 对准稳定判定         | 只有连续 3 个新视觉帧都在`±30 px` 内才进入 `TARGET_CONFIRM`                                                         | 防止单帧抖动误判为对准                          |
| 输出保持条件         | `TARGET_OUTPUT` 中必须持续满足 `fire_allowed=true` 且视觉未超时；正式链路中 `fire_allowed` 来自 P000 KEY 按住状态  | 松开 KEY 或视觉失效立即关断                     |
| 并发禁用保险         | `TARGET_OUTPUT` 在短临界区内再次检查 `ROBOT_TARGET_ENABLED`，只有仍启用时才调用 `BSP_Laser_On()`                   | 串口禁用和状态机同周期交错时不会重新点亮 P015   |
| 输出切断回传         | 从`TARGET_OUTPUT` 因许可撤销或视觉超时退出时回传 `RA6_TO_JETSON_OUTPUT=0`                                            | 上位机可同步显示输出已关闭                      |
| 调试命令隔离         | `laser_on/off` 只直接控制 P015，不改变 `ROBOT_TARGET_ENABLED`、P000 KEY 读取结果或状态机状态                         | 保留硬件调试能力，但不混入正式安全链路          |

当前限制必须明确记录：

- P000 KEY 已作为正式发射许可输入，默认按下为低电平；若上板实测相反，只需把 `LASER_FIRE_KEY_ACTIVE_LEVEL` 改为 `BSP_IO_LEVEL_HIGH`。

- Jetson 关闭控制帧 `AA 01 00 BB` 语义与 `target_disable` 一致，同样不是机械臂急停。
- `obs->estop_active` 和 `obs->limit_triggered` 已预留在 `target_obs_t`，当前周期任务尚未接入独立急停 GPIO；代码已检查关节限位状态 `ROBOT_STATUS_LIMIT_HAPPENED`。

### 7.2 上板验证建议

1. 执行 `soft_reset`，确认最终 HOME 校验通过且无需重复发送。
2. 运行 `read_all`，检查 J1~J5 批量反馈、耗时和 missing mask。
3. 运行 `auto 15 0 0`，记录运动平滑性、各关节 `ave_error` 和 CAN 超时日志。
4. 运行 `auto 0 -70 0`、`auto 0 -140 0` 和 `auto 0 0 100`，覆盖短路径、长路径和 Z 轴 S 曲线。
5. 修复并验证近零位移的单路径点边界，确认不会把关节目标误置为零。
6. 重复运行正负方向小位移，确认 IK 分支不跳变。
7. 在接近腕部奇异区前停止扩展测试；4.7 完成前不把奇异区运动视为已解决。
8. 上电后不启用 `ROBOT_TARGET_ENABLED`，测量 P015 应保持低电平。
9. 未执行 `soft_reset` 或 pose invalid 时发送 `target_enable`，确认命令被拒绝并提示先复位。
10. 发送 `target_disable` 后执行 `laser_on` / `laser_off`，确认串口调试能直接控制 P015。
11. `soft_reset` 成功后发送 `target_enable`，Jetson 连续发送合法视觉帧，确认 `TARGET_ALIGN` 只按 `±1.5 mm` 限幅小步修正。
12. 停止发送视觉帧超过 500 ms，确认状态机退出对准/输出并拉低 P015。
13. 触发任一关节限位，确认状态机进入 `TARGET_RECOVER`、P015 拉低，并回传 `RA6_TO_JETSON_ERROR=1`。
14. P000 KEY 未按下时，即使连续 3 帧对准，也不得进入激光输出；按住 P000 后才允许 `TARGET_OUTPUT`。
15. 在 `TARGET_OUTPUT` 中松开 P000，确认 P015 立即拉低并回传 `RA6_TO_JETSON_OUTPUT=0`。
16. 在 `TARGET_OUTPUT` 中发送 `target_disable`，确认 P015 立即拉低且不会被状态机重新点亮。
17. pose invalid 时发送 `AA 01 01 BB`，应回传 `CC 04 00 DD`，P015 保持低电平。
18. `soft_reset` 成功后发送 `AA 01 01 BB`，应回传 `CC 04 01 DD` 并进入预定位；任意时刻发送 `AA 01 00 BB`，应立即关闭 P015 并回传 `CC 04 00 DD`。
19. 回归现有视觉状态回传，确认 `READY`、`ALIGN_DONE`、`OUTPUT_ON/OFF` 不受 `FUNC=0x04` 启停回传影响。
