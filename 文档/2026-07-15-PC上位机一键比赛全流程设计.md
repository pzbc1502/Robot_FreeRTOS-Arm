# PC 上位机一键比赛全流程设计

日期：2026-07-15

## 1. 目标与范围

在现有 `UpperComputer` Qt 上位机中保留“一键定靶演示”，另外新增“一键比赛全流程”入口，用 PC 模拟 Jetson/Qt 端完整执行正式比赛流程。

本次只修改 PC 上位机，不修改 RA6M5 固件、正式视觉协议和现有命令行脚本。新流程必须复用上位机已经打开的 ARM 调试串口与 Jetson 模拟串口，不能启动会重复占用串口的子进程。

## 2. 采用方案

采用 GUI 内部后台执行器：

- GUI 继续拥有串口的唯一读写权。
- 正式协议的组帧、CRC16、解析、状态名称和序号信息统一放在 `UpperComputer/ra6m5_protocol.py`。
- 比赛流程由后台线程按步骤执行，通过线程安全的状态队列等待 RA6M5 回传。
- Qt 主线程只负责按钮、参数读取、进度显示和日志展示，不执行阻塞等待。
- 现有“一键定靶演示”保持原入口和用途，不与新流程合并。

不采用以下方案：

- 不从 GUI 启动 `DEBUG/formal_workflow_demo.py`，避免 COM7/COM14 被两个进程同时打开。
- 不把原“一键定靶演示”直接改成比赛全流程，保留局部定靶排障能力。

## 3. 界面设计

在 `Jetson/定靶` 页增加“比赛全流程模拟”分组，至少包含：

- 视图选择：左视图、正视图、右视图，默认正视图。
- 模拟安全距离：默认 `120 mm`。
- 视觉误差序列：默认 `20,-15:2;8,-6:2;0,0:0`。
- `开始一键比赛全流程` 按钮。
- `终止并保持` 按钮。
- 当前阶段标签，显示测距、拍摄、选图、定靶、等待 P000、输出、回 HOME 或故障。

流程运行期间禁止再次启动任何一键演示。原“一键定靶演示”和新比赛流程互斥；手动串口工具仍保留，但界面明确提示不要在比赛流程运行时发送运动命令。

## 4. 正式协议支持

上位机补齐当前固件使用的正式 `A5 5A + CRC16/MODBUS` 定义：

- `MSG_WORKFLOW_CTRL = 0x06`
- `EVENT_WORKFLOW = 0x20`
- `EVENT_COMMAND_ACK = 0x21`
- `WORKFLOW_START = 0x01`
- `WORKFLOW_FINISH = 0x02`
- `WORKFLOW_ABORT = 0x03`

正式状态解析结果必须保留：

- `TYPE`
- `SEQ`
- `EVENT`
- `VALUE`
- `ERROR`
- 原始帧

每条控制命令先等待同 `SEQ` 的 `COMMAND_ACK`。只有 `VALUE=1` 且 `ERROR=0` 才继续等待该命令对应的业务完成状态。异步错误帧允许使用 `SEQ=0x00`，不能被误判为普通命令应答。

## 5. 一键比赛流程

完整顺序固定为：

1. 检查 Jetson 模拟串口已打开、协议选择为正式协议，并确认没有其他演示线程运行。
2. 启动 200 ms 心跳。
3. 发送 `WORKFLOW START`，等待同序号 `COMMAND_ACK`。
4. 等待 `WORKFLOW_START_ACCEPTED`。
5. 等待机械臂完成回 HOME 和公共测距位 `(0, -130, -15)`，收到 `WORKFLOW_MEASURE_READY`。
6. 每 200 ms 发送一帧新的安全距离数据，共 3 帧且每帧使用不同 `SEQ`。
7. 等待 `WORKFLOW_SAFE_LATCHED`。
8. 发送 `CAPTURE HOME`，等待 HOME 完成。
9. 按“左视图、正视图、右视图”顺序逐点发送 `CAPTURE GOTO`；每次必须收到同序号 ACK 和对应拍摄点到达状态，才发送下一点。
10. 三视图完成后发送 `CAPTURE HOME`，等待回 HOME。
11. 按界面选择发送 `CAPTURE SELECT`，等待机械臂到达选中视图点。
12. 发送 `TARGET START`，等待同序号 ACK、`TARGET_CTRL_ON` 和 `READY`。
13. 按 200 ms 周期发送视觉误差序列，等待 `ALIGN_DONE`。
14. 提示用户按住 P000，等待 `OUTPUT_ON`。
15. 提示用户松开 P000，等待 `OUTPUT_OFF`，随后停止视觉误差发送。
16. 发送 `WORKFLOW FINISH`，等待同序号 ACK 和 `WORKFLOW_RETURN_HOME_DONE`。
17. 停止心跳，恢复按钮，流程显示完成。

GUI 不模拟 P000。物理按键仍是激光输出的必要许可，不能由软件跳过。

## 6. 停止与异常处理

用户点击“终止并保持”、等待超时、收到 RA6M5 错误帧、串口断开或流程线程异常时，执行统一收尾：

1. 停止视觉误差发送和安全距离发送。
2. 尝试发送 `WORKFLOW ABORT` 并等待短时 ACK。
3. 停止当前演示心跳。
4. 显示失败阶段、错误码和最近一次有效状态。
5. 保持机械臂当前位置，不自动发送 `soft_reset`。

固件负责在 ABORT、心跳超时和其他安全故障时关闭 P015。GUI 的终止语义是“停止并保持”，不是“自动回 HOME”。恢复后必须由用户重新点击“开始一键比赛全流程”，固件会先回 HOME 再进入公共测距位。

## 7. 并发与串口所有权

- 新流程不创建新的 `serial.Serial` 对象。
- 所有发送都复用现有 `SerialChannel.write()`，沿用其发送锁。
- 串口接收仍由现有读取线程完成；解析后将正式状态同时送给界面状态灯和比赛流程等待队列。
- 状态等待按 `SEQ + EVENT + VALUE` 匹配，不能只按状态名称匹配。
- 开始新流程前清空旧状态队列，避免上一次运行的迟到帧推进新流程。
- 原一键定靶线程与新比赛流程线程使用统一互斥标志，任何时刻最多运行一个自动演示。

## 8. 文件改动范围

- `UpperComputer/ra6m5_protocol.py`
  - 补齐 workflow 协议常量、组帧函数和带 SEQ 的正式状态解析结果。
- `UpperComputer/ra6m5_upper_console.py`
  - 增加比赛流程界面、后台执行器、进度状态和统一终止逻辑。
  - 保留原“一键定靶演示”。
- `DEBUG/test_upper_console_protocol.py`
  - 增加 workflow 帧、ACK、业务状态、错误帧和分包解析测试。
- `DEBUG/test_upper_console_gui_features.py`
  - 检查新按钮、参数控件、互斥逻辑和状态显示。
- 视需要增加一个只测试流程顺序的静态/单元测试文件。

不修改 `APP`、`Middle`、`USER_BSP`、Keil 工程和 RA6M5 固件。

## 9. 验收标准

- 原“一键定靶演示”仍可独立使用。
- 新按钮在 Qt 主线程不冻结的情况下完成正式比赛流程。
- 每条控制命令都等待同 `SEQ` ACK，不会被旧帧或异步帧误推进。
- 安全距离严格发送 3 个不同 `SEQ` 的有效样本。
- 拍摄严格执行 HOME、左、正、右、HOME、选择视图。
- ALIGN_DONE 后必须由物理 P000 才能进入 OUTPUT。
- 正常完成后 RA6M5 回 HOME；终止或故障时保持当前位置并关闭激光。
- Python 语法检查、协议测试、GUI smoke test 和现有 UpperComputer 测试全部通过。
- 重新打包生成新的 `RA6M5_Robot_Console.exe`，并保留源码直接运行方式。
